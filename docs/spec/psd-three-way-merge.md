# PSD 节点树与预览合并工作台

Status: Draft
Date: 2026-11-13
Scope: 在 VS Code 扩展中比较两份 PSD，依据共同基础版本合并图层，逐项选择来源并预览、另存合并结果。本次交付方案及示例交互，不包含真实 PSD 解码、合成或写出实现。

## 1. Context

用户认可已有 Prefab 的增量同步方案，并提出第二个协作需求：PSD 也需要冲突合并。参考草图为左上、左下两份输入，右侧一个较大的输出区域；每个区域均由节点树和预览组成，在左边选择使用哪一份内容，右边展示合并结果。

沿用 [整体方案](prototype-layaui-prefab-psd.md) 的稳定身份、PSD 关联、只读输入和显式采用边界。三块可见区域分别是 A、B、结果；真正三方合并的输入为基础版本 Base、版本 A、版本 B，结果是第四份文档。Base 默认从顶部入口按需查看，不增加常驻第四块区域。

## 2. Goals

- 按用户草图提供上下排列的两个来源区和右侧结果区，每区都有图层树及预览。
- 用户可按图层、图层组选择来源，选择后结果树和结果画面同步更新，并支持撤销。
- 有可靠 Base 时识别两边的修改、增删和冲突；无 Base 时仍能手动组合两份 PSD。
- 保留图层身份、父子关系、叠放顺序和需要共同处理的依赖，输出可继续由美术编辑的 PSD。
- 将合并后的 PSD 作为新的美术版本关联到原型，资源回流继续走既有审阅流程。

## 3. Non-Goals

- 首版不做 Photoshop 绘画、逐像素冲突融合、AI 自动重绘或全部 PSD 特性的重实现。
- 不把两份整图叠加当成分层 PSD 合并；不宣称普通 JavaScript 解析器可无损保存所有高级特性。
- 不通过合并操作自动更新原型布局、游戏资源或 Prefab。
- 本次不修改扩展运行时代码，也不声称示例中的图形来自真实 PSD。

## 4. Current Behavior

GameFlow 目前具备原型编辑和稳定短 ID。PSD 读取、关联、导出及美术回流仍处于 Draft；本功能依赖它们的资源引用和能力检查。源 PSD 可读取合成图不代表合并结果已经能够准确渲染或重新写出。

## 5. Proposed Behavior

### 5.1 工作台布局

```text
PSD 合并   A: 登录-A.psd   B: 登录-B.psd   基础: 登录-v1.psd [查看]
┌──────────────────────────┐  ┌─────────────────────────────────┐
│ 来源 A                   │  │ 合并结果 · 待处理 2 项            │
│ ☑ 层级树         │ 预览  │  │                                 │
│                  │       │  │ 结果图层树 │ 结果预览             │
├──────────────────────────┤  │ 来源/冲突  │                     │
│ 来源 B                   │  │            │                     │
│ ☑ 层级树         │ 预览  │  │            │                     │
│                  │       │  │                                 │
└──────────────────────────┘  └─────────────────────────────────┘
选中节点：差异与依赖    [保留基础版本]    [另存结果]
```

三个区域的树/预览比例可调整。点击任一树节点或可命中的图层区域，其他两区联动定位同一个逻辑节点；放大和平移默认同步，也可解除。预览始终使用文档设计坐标，视口缩放不能改变 PSD 像素或层边界。窄窗口切换 A/B/结果标签，保留选中节点及视角。

输入区只读；来源采用使用树节点前的原生 checkbox，替换逐行“采用”按钮。树包含可展开/折叠的图层组、多级缩进与层级连线，右侧结果使用相同层级结构。展开箭头只控制折叠，点击名称只选中定位，checkbox 只控制采用来源；图层自身可见性仍是独立的 PSD 内容属性。

勾选叶节点表示采用此来源的图层；同一匹配节点的 A/B checkbox 互斥。取消勾选当前来源表示撤回该选择，恢复为待处理，不自动选择另一边、删除或隐藏节点。两边都未勾选可能是待处理或已显式采用 Base，需以结果状态区别。删除项保留带“删除”标记的占位节点，勾选它才表示采用删除。

勾选组会选择其所有后代，包括折叠后不可见的后代；组的全选、未选、半选由后代来源选择推导。半选组再点击为整组采用。取消全选组时只撤销属于该来源的后代选择，保留其他来源的决定。整组变化作为一个可撤销操作，涉及依赖或已处理子项时仍显示其影响。保留两份必须是显式复制决策，不以同时勾选 A/B 暗示复制。

结果节点标明来自 A、B、Base、自动合并或手动调整。结果仍有冲突时显示明确的临时预览状态；待处理节点可暂用 Base 内容显示，但这不代表已经接受 Base。无 Base 的未选择节点不擅自采用一边。状态用紧凑文字/标记呈现，完整差异在选中详情展开。

选中冲突时显示 Base/A/B 的相关属性或小预览，以及依赖范围。首版支持采用一方完整图层/组、采用删除、保留 Base；“保留两份”生成两个独立结果节点，明确名称和前后顺序。可独立验证的属性后续增加细项选择。采用整组会显示将覆盖的子项决策，作为一个可撤销操作。

结果区支持查看完整结果树与来源；重排/改父级作为显式合并操作逐步开放。执行后重新校验裁剪、蒙版、依赖和冲突。首版不提供自由绘制或任意修改像素。

### 5.2 Base 的来源和缺失处理

- 首选已记录的共同祖先 PSD：GameFlow 美术交付保存的完整快照，或用户明确选定的版本文件。需要完整图层内容和资源，只有 hash 或原型 JSON 不足以作为 PSD Base。
- 有版本管理时可以由适配器取共同历史版本，但必须得到实际文件及内容指纹；“上次见到的 PSD”不自动等于两边共同祖先。
- 任意两份独立 PSD 仍可打开，界面明确显示“手动合成 · 无基础版本”。此模式不自动认定哪边修改/删除、不伪造三方比较结论。
- 文档尺寸、色彩模式、位深、ICC 配置、画板/坐标基准先对齐；相互冲突时显式选择结果规格或执行有预览的转换。缩放预览不能代替转换。

## 6. Design

### 6.1 逻辑节点与 PSD 身份

PSD 节点包括图层组、像素层、文字层、形状层、调整图层、智能对象等；不是每种节点都映射一个游戏控件。一个原型节点可以对应多个 PSD 图层及不同状态。

节点身份只由元数据及已建立的身份记录决定：文档谱系/关联 ID + GameFlow 图层 ID。名称和路径用于展示/搜索，像素、图形相似度、文字内容及几何重合不参与身份匹配，不据此推断图层来源或合并关系。PSD 原生数字 ID 是同源基线中的辅助记录，不能替代缺失的 GameFlow 身份；独立文件中的相同原生 ID 不代表同一层。

原型沿用 8 位节点 ID；PSD 保留其原生图层 ID 格式，二者用清单映射，不能把短字符串直接填入 PSD 数字 ID。结果延续已有逻辑身份；新增层与“保留两份”的副本获得新身份，输出图层 ID 在结果文件内唯一，并同步改写依赖引用。来源 A/B/Base 的 ID 保持原值。

#### 6.1.1 元数据管理规则（2026-11-13 用户确认）

本节的“图层合并”指在 Photoshop 中把多层合成一个新对象；工作台选择 A/B 的已有节点组装结果时，仍按各节点元数据延续身份。

| 元数据状态 / 操作 | 身份处理 |
| --- | --- |
| 同谱系内有效且唯一的 GameFlow ID | 延续原对象；改名、移动、缩放或图像修改不改变身份 |
| 同文件中重复的 GameFlow ID | 收集所有重复项，不能按 ID 建单值表覆盖；有唯一历史记录时保留原层身份，为副本分配新 ID；否则处理元数据歧义，不用图像判断原件 |
| 没有 GameFlow 身份元数据 | 按新对象导入并分配新 ID；适用于新增、重建及合并后的无元数据层，即使原生 ID 沿用也不恢复旧身份 |
| 历史 ID 在当前文件中消失 | 记为原美术对象消失、旧关联失效；不推断它被合并到了哪个新层，不自动删除原型节点 |
| 图层合并 | 合并结果是新对象，采用新 ID，不继承旧层的身份、控件角色或绑定，不要求确认/恢复多对一来源 |
| 元数据格式损坏、版本不支持或谱系歧义 | 报告元数据问题，不静默覆盖或按新对象吞掉错误 |

新身份在接受导入/输出时持久化，刷新预览不写源 PSD、不反复生成身份。新对象需要原型绑定时建立新的明确关联，不通过内容相似度恢复旧绑定。

系统只对实际元数据负责：受控的图层合并操作应清除旧身份并分配新身份；若第三方工具合并后仍保留完整有效的旧 ID，单靠元数据不能识别这个操作，应由操作端或显式“作为新对象”重置身份，不引入像素分析来兜底。

### 6.2 合并会话

会话记录以下持久信息；缩略图和可重建的解码缓存不放入会话 JSON：

| 信息 | 用途 |
| --- | --- |
| sessionId、来源引用、完整内容指纹、不可变快照位置 | 关联准确的 Base/A/B 版本，避免继续会话时读取到不同文件 |
| 解析/渲染/写出能力版本、目标文档规格 | 保证比较与输出可复现 |
| 图层逻辑 ID、来源映射、父子/叠放关系 | 对齐树与依赖 |
| 变化集、冲突原因、依赖范围 | 区分可自动处理与必须决策的内容 |
| 选择记录与撤销栈 | 采用来源、删除、保留两份和重排；记录作用于层还是整个组 |
| 结果节点树、未解决项、预览修订号 | 驱动结果树和预览，防止显示旧任务结果 |
| 输出谱系与原型映射候选 | 追踪输出来自哪些版本；后续审阅更新原型关联 |

源文件变化时提示创建新会话快照或重新计算差异，不能在用户审阅中悄悄换掉来源内容。重新计算时仅重用输入未变的决策，其余明确标为需要复核。跨工作区路径按整体方案处理，不能把本机绝对路径当作团队共享身份。

### 6.3 比较与合并规则

有共同 Base 时，对已经匹配的节点和受支持的属性组比较：

| A 相对 Base | B 相对 Base | 结果 |
| --- | --- | --- |
| 未变 | 未变 | 保留 |
| 修改 | 未变 | 采用 A 的修改 |
| 未变 | 修改 | 采用 B 的修改 |
| 改成相同结果 | 改成相同结果 | 采用共同结果 |
| 修改不同且相互独立的属性 | 修改不同且相互独立的属性 | 验证依赖后组合 |
| 同一内容/属性组改成不同结果 | 同一内容/属性组改成不同结果 | 冲突，等待选择 |
| 删除 | 未变 | 采用删除；仍检查结构和依赖 |
| 删除 | 修改/移入子层 | 删除与修改冲突 |

两边独立新增的不同节点可以同时保留，但要校验身份、插入位置和依赖；同一 ID 新增不同内容、同一位置的排序歧义需处理。双方都删除的节点删除。改名通过身份追踪，不当作删除再新增。

基础粒度为完整图层/依赖组；属性级合并只开放验证通过的独立属性。图层视觉载荷作为整体选择 A 或 B，不分析画面语义、不自动逐像素拼接。文字内容、字体、文本框及变换具有依赖；图层 bounds、像素原点和 transform 也不能随意跨版本组合。版本/hash 可用于变更及缓存检测，不能作为节点身份或合并来源的依据；预览与输出合成负责显示选中的实际内容。

子节点顺序按身份和前后关系合并，父子关系单独处理；输出禁止循环、悬空父节点和丢失引用。Base 的 sibling 索引不能直接当作新树的稳定主键。

### 6.4 PSD 特有依赖

蒙版、剪贴图层及被剪贴底层、组混合模式、调整图层影响范围、图层效果、链接层/智能对象依赖可能跨越普通父子树。采用前计算需要共同处理的范围，显示“将同时采用这些层/效果”；不自动带入用户未看到的依赖。

需要整体保留的内容作为不可拆分的依赖组。可以选择另一方完整组，或进入支持这些特性的 Photoshop 流程。保留两份时也必须复制并重映射组内关联；不能复制一个蒙版而丢失其对应内容。

独立字段没有冲突不保证最终视觉一致，尤其是 pass-through 组和调整图层；结果必须重新合成并审阅。未知元数据原样读取并不代表重写后仍能无损保留，支持范围必须由读写往返验证确认。

### 6.5 三块预览的来源

- A/B 初始整图可以使用源 PSD 保存的合成图，获得美术原稿效果；树命中/高亮使用解析的边界，在不支持精确命中时说明是边界选择。
- 结果预览必须根据结果节点树和完整依赖重新渲染，不能仅拼接 A/B 的整图。改变采用项、层次和可见性都会影响合成。
- 首轮引擎只处理经过验证的 8-bit RGB/RGBA 和基础图层特性。高级特性需要评估 Photoshop 桥接，在复制出的文档中执行节点操作，生成最终合成图及 PSD；桥接的可用性和保真度要实测。
- 尚不具备准确合成/写出能力时，可以保存合并决策会话并显示明确的近似预览，但不能提供宣称无损的完成导出。用户明确选择的栅格化版本属于另一种交付，不能静默替代可编辑 PSD。
- 合成任务异步、可取消，按会话修订号接收结果；新选择产生后丢弃旧渲染回包。对三份输入和结果设置合计资源预算，按需解码、缓存和释放，不一次展开全部图层位图阻塞扩展宿主。

### 6.6 输出和原型衔接

“保存合并会话”允许有未解决项；“另存合并 PSD”要求映射、文档规格、结构依赖和冲突均已处理，且目标功能在写出能力范围内。输出到新 PSD，保持 A/B/Base 不变；另存路径冲突按显式替换流程处理。

输出包括 PSD、与结果一致的新合成图，以及记录父版本、稳定身份映射和采用决策的清单。写出后重新读取验证节点、ID 和基础合成结果；关键样例用 Photoshop 打开/保存验证文字、效果及图层可编辑性。二进制 PSD 和清单一起准备，失败不标记完成，避免旧合成图冒充新结果。

合并成功后提供“作为此页面的新美术版本”操作，更新 PSD 关联及可复用的节点/图层映射；失效的一对多映射列出复核。采用切图到原型、原型布局变化和 Prefab 更新仍是各自独立的审阅事务。

## 7. Implementation Plan

1. 交互验证：使用示例节点展示两个来源树/预览、逐层采用、冲突计数、结果联动及撤销。明确这是交互示意。
2. 读取和手动合成：实际读取两份受支持 PSD，建立映射，显示真实合成图；先保存选择会话，接入通过验证的结果渲染器后才开放对应输出。
3. 真正三方比较：加入共同 Base、变化检测、自动合并和冲突列表，覆盖增删/重排及属性依赖。
4. 可编辑结果：完成受支持特性的结果 PSD 写出、重读和 Photoshop 往返验证；对高级特性验证桥接路线后扩充支持。
5. 原型衔接：将结果关联到页面，复核图层绑定，再接入资源回流与 Prefab 更新。

当前用户已确认所需布局和能力方向；具体 PSD 解析/写出选型及高级特性支持表仍待实施验证。本文件不是全部功能的已交付基线。

## 8. Testing Plan

- 比较：单边修改、相同修改、不同属性修改、像素冲突、删除/修改、两边删除、独立新增、同 ID 不同内容、改名、重排和跨组移动。
- 身份：已知同源、独立同 ID、缺失 ID、复制重复 ID、合并作为新对象、重复组名、保留两份后的输出 ID 与原型一对多绑定。即使新层像素与旧层相同、或原生 ID 沿用，缺少 GameFlow 身份时也不继承旧对象；身份判断不调用内容分析。
- 依赖：剪贴链、蒙版、调整图层、组 pass-through、文字变换、智能对象与链接资源；验证部分采用不会产生无效结构或错误效果。
- 交互：真实多级树展开/折叠、checkbox 互斥与取消、父组全选/半选（含隐藏后代）、组操作一次撤销、三树联动、预览命中、冲突定位、删除占位、窄窗口、键盘操作和取消。
- 会话：保存/恢复、源文件变更、Base 丢失、晚到的渲染结果、改用不同输出色彩规格、解析/写出版本变化。
- 产物：重新读取与 Photoshop 打开/再次保存，检查层、组、文字可编辑性、透明度、效果和新合成图；输入文件字节保持不变。
- 性能：复用整体方案真实 PSD fixture，对三输入与结果共同记录总内存、首显、逐项更新延迟及取消时延，按目标设备确定预算。

## 9. Acceptance Criteria

- 两个来源区上下排列、结果区在右，三者都包含节点树与预览；逐节点采用能同时改变结果树、来源标记和画面。
- 来源树使用 checkbox，具有组与子节点的真实层级、展开/折叠和父组半选；切换来源时对应项互斥，取消选择不会被误解为删除。结果区保留同样的可展开树。
- Base 的身份和来源可查看；无 Base 时明确显示手动模式，不能给出未经依据的单边修改/删除结论。
- 确认同源后，单边改动可自动采用；双方修改同一内容到不同结果时保留待处理状态，直到用户作出决策。
- 删除与修改、依赖不完整及身份歧义均不能被静默处理；已采用的选择可以撤销并准确恢复冲突状态。
- 合并后的对象采用新身份，缺失元数据层走新对象流程；不要求分析像素或恢复多对一来源。副本的新身份、消失身份和失效绑定均可从元数据记录解释。
- 结果 PSD 可继续美术加工，且合成图对应实际结果树；不支持的内容明确阻止对应输出或由经验证的桥接处理。
- 合并完成不会自动改写原型、源 PSD 或 Prefab，后续采用流程可追踪结果谱系。

## 10. Risks and Rollback

- Base 或谱系错误会导致错误自动合并：始终记录完整来源，缺失时使用手动模式，匹配歧义显式解决。
- PSD 视觉依赖超出树结构：按依赖范围合并并验证真实渲染；首版限制支持范围。
- 解析器写出丢失高级信息：采用往返 fixture 作为能力门槛，不能通过“保留未知 JSON 字段”承诺 PSD 无损。
- 合并操作失误：只读来源、操作级撤销、保存会话与新文件输出；失败清理仅限本次临时产物，源文件和先前成功结果保留。
- 整体方案维持 Draft，本次示例交互不改变现有扩展基线。
