# Prototype Panel Top Alignment

Status: Done
Date: 2026-11-13
Scope: 原型浮动面板 280px 等宽、顶部跟随及 400px 可用高度阈值

## Context and Goals

现有图层/属性宽度为 216/264px。共享定位按面板完整高度钳制 top，长属性面板为避免底部越界会被抬高，无法与画板顶部对齐。用户要求两侧宽度 280px，右侧顶部与内容顶部对齐，可用高度低于 400px 时停止跟随。

## Behavior and Design

- 两侧标准宽度均为 280px，继续按页面边界水平定位并保留 16px 间隔；窄窗口等比例缩窄，始终在屏幕内。
- 两侧 top 优先跟随画板内容顶部，以底部工具栏/缩放条上沿减边距作为下边界；maxHeight 为此下边界减当前 top。长内容在面板内部滚动，标题不被挤走。
- 向下跟随将使可用高度小于 400px 时，top 停在保留 400px 的位置。400px 是可用高度的阈值，不强制拉长短面板或折叠面板。窗口本身不足 400px 时使用实际可用空间；内容顶部越过上边界时保留屏幕边距。
- 收起/展开或切换节点不根据面板完整高度重新抬高 top；返回可跟随区间后继续对齐。相机、文档、ID 与撤销栈均不改变。
- 共享算法新增可选 minFollowHeight；原型设为 400。未指定时保持原先基于实际面板高度的定位，PSD 不改变。

## Implementation and Acceptance

1. 扩展纯面板算法并接入原型参数，统一默认 CSS 宽度。
2. 更新原型定位测试：顶部与内容对齐、面板高度变化不跳动、400px 停止/恢复、短窗口、极端越界；既有 PSD 测试通过。
3. 浏览器在长属性面板下确认 280px 宽、顶部对齐、内部滚动，以及平移超过阈值后的停止跟随；验证窄/矮窗口。
4. 构建、测试通过，同步基线与原跟随面板工作项。

## Risks and Rollback

画板接近屏幕下方时面板会比画板顶部高，这是保留 400px 可操作高度的预期行为。禁用可选参数可恢复原算法，不影响持久化数据。

## Verification Record

- 更新两项原型面板测试并新增阈值回归；全部 72 项测试通过，既有 PSD 面板定位测试不变且通过。
- 浏览器 1280×720：画板和左右面板均 top=236，面板宽度均 280，属性 maxHeight=410。
- 画板下移到 top=386 后，两面板停在 top=246，可用高度=400；内部滚动不改变画板位置。画板移回 top=236 后面板恢复对齐。
- 360×320 窗口两侧各宽 160，top=52、可用高度=152；两面板互不重叠且底部 204，低于缩放条上沿 216。已恢复默认视口。
- 构建通过，浏览器无 console error；本轮不涉及文档数据变化。
