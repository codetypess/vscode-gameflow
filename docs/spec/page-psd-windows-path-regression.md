# 页面 PSD 的 Windows 相对路径修复

状态：Done（2026-11-19）

## 背景与根因

页面绑定提示“无法保存此 PSD 的相对路径，请选择 GameFlow 同一磁盘中的文件”。PagePsdController.relativeSource 对所有 URI 直接使用 posix.relative。Windows 的本地文件 URI.path 会保留 D:/d: 和目录大小写，POSIX 算法将这些视为不同目录，生成包含 ../../D:/ 的伪相对路径，随后被 isPagePsdSource 的冒号限制拒绝。使用截图中同目录示例路径只改变盘符大小写即可复现同一错误；不是取消选择、权限或实际文件读取失败，因为错误发生在文件读取/生成写入前。

## 目标与边界

- 本地 Windows 盘符 URI 使用 Windows 路径语义计算相对路径，盘符和共同目录大小写差异不误报；保留目标路径及文件名大小写，持久化统一使用 /。
- 生成、绑定、按已保存绑定读取与另存为重算路径共用修复。
- 真正跨盘、跨文件系统及非法相对路径继续拒绝，生成失败不得提前写入 PSD。
- POSIX 和远程 URI 继续采用区分大小写的 URI 路径语义。
- 不修改源文档格式，不清除或迁移既有绑定，不改更多菜单交互，不将 PSD 自动绑定页面。

## 设计

在宿主 relativeSource 边界识别 file scheme 且双方 URI.path 为 /X:/ 的本地盘符路径，去除 URI 的盘符前缀 / 后用 node:path.win32.dirname/relative 计算，并把输出反斜线转换为 /。其他路径维持 posix 算法。仍先校验 scheme/authority，随后通过既有 isPagePsdSource 校验拒绝绝对路径和非法输出。

## 实施与验收

1. 共享宿主回归重现绑定和生成在盘符/目录大小写差异时失败；覆盖真正跨盘不会写入/载入，另存为重算路径和远程大小写边界。
2. 修复相对路径责任边界，不降低文档路径校验。
3. 真实 VS Code URI 的盘符大小写组合和另存为重算验证，保留实际保存/重开回归。
4. 运行共享测试、PSD 宿主、生产构建和 diff 检查。

## 风险

只将本地盘符形式文件 URI 交给 Windows 算法，避免把 Linux/远程路径一并忽略大小写。UNC 及不带盘符的 URI 保持既有语义。修复不处理符号链接或移动磁盘后的资源重定位。

## 验证结果

- 修复前新增共享回归在 Windows 选择/生成与另存为两个测试处失败，报错与用户截图一致；修复后 362 项共享测试通过。
- 新增覆盖共同目录和盘符大小写差异、中文与大写扩展名保留、真正跨盘在载入/生成前失败且不写入、不修改页面模型，以及远程 POSIX 目录大小写区别。
- 真实 VS Code 宿主采用原 URI 的相反盘符大小写执行另存为，验证实际 URI.path 差异、保存的相对 PSD 路径与原有保存重开；49 项宿主检查通过。
- npm run build（含双端类型检查）与 git diff --check 通过；此变更仅修改宿主路径计算，既有更多菜单与未提交界面改动保留。
