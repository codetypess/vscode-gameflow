# 画布保存时确认覆盖

Status: Done

工作台编辑过画布，磁盘上的同一份文件也被修改时，`saveCustomDocument` 比对保存基线后直接抛错。VS Code 的 Retry 再次调用相同的保存流程，用户无法在这次保存中选择采用自己的草稿。

顶栏保存和 Ctrl+S 共用原生工作台保存入口。宿主发现将覆盖外部修改时，在写入前显示文件名并提供「覆盖保存」与取消。确认后将工作台草稿写回原路径，成功后更新保存基线。取消或关闭提示保留外部文件、可恢复的草稿和未保存标记。磁盘内容已等于待保存草稿时直接完成保存。

确认仅适用于提示时的磁盘内容。等待确认期间又出现另一份外部修改时重新询问。聚合保存先处理已知的画布冲突，再保存关联的 PSD 配置。删除后的画布沿用原路径重建规则。

宿主回归使用打开的工作台画布，先编辑草稿，再从外部改写文件。检查取消后的磁盘、草稿与标签状态，检查再次保存并确认后写入的内容、后续普通保存，以及等待确认期间的外部改写。

2026-11-27 在 VS Code 扩展宿主中复现了旧版直接抛错。修复后生产构建、417 项共享测试及 64 项宿主检查通过，其中覆盖了取消时保留关联 PSD 草稿、确认后继续保存、再次外部改写和磁盘已等于草稿的情况。
