# Extension Architecture Baseline

Date: 2026-11-14
Status: Baseline for the initial extension scaffold

## Runtime Layers

1. VS Code extension host owns document IO, validation, commands, save/undo integration and Webview lifecycle.
2. React Webview owns presentation and local interaction state. It has no arbitrary filesystem access or extension secrets. VS Code PSD slicing uses a host-selected source URI and a dedicated custom document; browser slicing and merge-source Files use the browser File API. Writes in VS Code remain host-owned.
3. `shared/` owns document contracts, validation, ID allocation and host/Webview messages. Secure Nano ID supplies identity generation; pinned `pinyin-pro` 3.29.5 supplies PSD export-name syllable initials.
4. Build adapters stay at the boundary: esbuild for the extension host and Vite for the browser Webview.
5. The Webview uses local shadcn/ui component source and design tokens mapped to VS Code theme variables; runtime UI assets must not depend on a CDN. Shared entry styles explicitly reset root margin and padding to zero, overriding VS Code's injected body padding so the workspace fills the Webview in both extension and browser environments.

## Document Rules

- A `*.gameflow.json` `TextDocument` is the initial persisted authority.
- Webview changes are candidate documents; the host validates them before applying a `WorkspaceEdit`.
- Parsing or validation failure must not overwrite source content.
- Document format is versioned. Stable IDs, world coordinates and page-local node coordinates are persisted independently.
- Optional v2 `page.rootType` identifies UIStack, UITop, UIScene or a standalone UIBox component board. Missing values are interpreted as UIStack without normalizing saved content. Root type is independent of `kind` (screen/modal); v1 rejects explicit rootType, and the existing first-edit upgrade preserves IDs and supports undo.
- Optional v2 `page.layout` stores the six root constraints and their absolute/percent unit relative to a future runtime parent. It accepts only ConstraintLayout fields, rejecting unknown fields, malformed values and v1 payloads at shared codec/message and JSON Schema boundaries. Canvas placement and design size remain page.frame, and node layout resolution ignores root constraints. Normal transactions provide save/history and first-edit upgrades; page copies clone root layout independently. No parent preview or Prefab generation is implied.
- Optional v2 `node.variableName` is independent of display name and identity. Shared validation enforces portable ASCII JS/TS binding syntax, excludes reserved/strict binding words and rejects case-sensitive duplicate variables per page with both paths. JSON Schema mirrors syntax/reserved words and rejects the field in v1; normal editor transactions upgrade v1 on the first variable edit. Subtree duplicate/paste allocates available variable names in the target page, while page copies retain their own scope. No runtime bindings or generated code are implied by the stored field.
- Optional v2 `node.transform` stores anchors, scale, skew and rotation with no read-time default insertion. Shared validation and JSON Schema reject unknown fields, out-of-range anchors and v1 transform fields; the runtime additionally checks finite numbers. Shared affine geometry composes parent transforms and scroll after layout, and drives rendering, clipping, selection and inverse editing. Resolved matrices, polygons and bounding boxes remain transient; normal transactions, save and history retain authored transform precision and stable IDs.
- Anchor editing is one page transaction through `setNodeAnchor`, preserving world geometry while converting the authored position. Optional finite v2 `layout.positionOffsetX/Y` retain compensation where automatic placement, measurement or constraint rounding would override frame coordinates. They apply after base layout, do not contribute to measurement or occupancy, and are consumed by shared inverse editing. Reparent, root paste and container-layout conversion absorb them into frozen local geometry and clear them.
- View-only state such as camera position and active tool is not required in the initial persisted document.
- Prototype and PSD slice canvases share `CanvasDots` and `webview/lib/canvas-grid.ts`. Dot spacing cycles between 24px inclusive and 48px exclusive at power-of-two zoom levels, with constant screen-space dot size and bounded background offsets anchored at world zero. Grid geometry is decorative and never changes authored coordinates, snapping or saved data.
- Prototype and PSD panels share `webview/lib/canvas-panels.ts` for screen-space anchoring and viewport limits. The prototype observes viewport, panel and bottom-control bounds; its panels follow the current page, independently of node selection. Panel geometry never enters document transactions or undo history.
- Prototype panels opt into `minFollowHeight: 400`: top follows the page while available height shrinks, then stops to retain 400px (bounded by the viewport). Both widths are 280px before responsive shrinking. PSD omits the option and retains its existing measured-height placement.
- New page/control identities use secure Nano ID `customAlphabet("abcdefghijklmnopqrstuvwxyz0123456789", 8)`, matching Laya's length while permitting numeric first characters. The editor reserves IDs across the current document and allocations seen during its session, including IDs later removed by delete/undo. Copies receive new IDs and remapped internal references. All page and node IDs share one document-wide namespace: shared validation rejects duplicates and reports both JSON paths without renumbering, protecting parsing, serialization and edit messages. Cross-document identity includes documentId plus element ID; pageId can locate the owning page. Eight-character IDs are not globally unique resource UUIDs.
- The optional v1/v2 `elementIdScheme` accepts only `"nanoid-8"`. New documents and migrated samples carry it. On the first valid editor init, DocumentSession calls the validated shared migration helper for an unmarked document: reserve old identities, allocate all page/control IDs, rewrite parentId and page-navigation endpoints, and add the marker. It submits one normal `edit` transaction, including the existing v1-to-v2 first-edit upgrade. Host acknowledgement/save ordering and undo apply as usual; repeated init, snapshots and undo in that session do not rerun migration. A marked document is a no-op on reload. Codec functions remain pure and retain legacy identities; only the migration transaction changes them. Document/requirement/interaction IDs are unchanged, and unsupported markers or ambiguous inputs fail validation before allocation.

## Protocol Rules

- Raw messages use discriminated unions shared by host and Webview.
- Webview first sends `ready`; host answers with `init` or `documentError`.
- Accepted edits produce normal TextDocument changes, and the host then broadcasts a fresh `documentChanged` snapshot.
- Webview keeps one candidate edit in flight and replaces a queued candidate with the latest state. Save/undo/redo are serialized after the edit acknowledgement and complete with an explicit fixed action message; duplicate document snapshots are not command acknowledgements.
- The protocol contains no arbitrary command execution. Reference navigation accepts only validated relative `.gameflow.json` source keys already present in the host dependency registry; file selection is host-owned.

## PSD Session Boundary

- PSD slicing in VS Code is owned by `PsdEditorProvider` / `PsdDocumentModel`, registered as `gameflow.psdEditor`. A PSD URI identifies the logical configuration document; normal save writes the adjacent sidecar. `CustomDocumentEditEvent` delegates dirty tabs, close confirmation and native history to VS Code. Prototype JSON is never changed to simulate PSD dirty state. Workbench `openPsdEditor` requests invoke a native picker; the command also supports explicit Explorer/open-with URIs. Webview file drops require locating the source in the picker because browser Files do not expose trusted paths.
- `shared/psd-structure.ts` initializes metadata identically in the host and Worker; the host owns metadata revisions and the Worker adds transient decoded pixels. `psd-draft.ts` snapshots configurations/identities without pixels and validates source hashes, layer keys and grid bounds; duplicates remain representable in recovery drafts, while formal sidecar save rejects them. `psd-editor-protocol.ts` is isolated from prototype edit sequencing.
- `PsdDocumentSession` serializes optimistic metadata candidates, preserves rejected edits for explicit retry, and queues save/history after edits. Native save/backup flushes preceding Webview edits via an explicit acknowledgement. Initialization preserves state arriving during pixel decode. Save records the written snapshot as baseline; newer edits remain dirty. Host writes verify source/sidecar fingerprints and dirty text targets, write a temporary sibling then rename, and preserve dirty state on failure.
- Automatic draft checkpoints live under extension global storage, with the source snapshot stored once and versioned metadata persisted separately. `backupCustomDocument` produces a self-contained recovery envelope at VS Code's backup destination. Backup completion is separate from save completion. Save/revert clears recovery files; explicit discard remains available when external files have become unreadable. Invalid backups are retained with diagnostics. Source-mismatched sidecars remain intact while identity repair stays editable, and replacement requires an explicit UI choice.
- Browser slicing retains File imports and local configuration history, with source-name/hash-keyed localStorage draft recovery after reselecting the same PSD. Browser downloads do not claim disk-write acknowledgement. Merge previews retain transient local Files and existing modal/drop guards.
- The slice canvas owns its view-only camera. Side panels use screen-space bounds derived from the PSD camera and measured viewport/panel sizes; they are not part of the scaled artwork. Hidden zero-size observations are ignored, and panel actions do not start canvas gestures. Camera changes never dirty PSD metadata or enter configuration undo history.
- Canvas picking maps screen coordinates through the camera and respects the decoded top-to-bottom layer order. Text-layer classification and lazily cached one-bit PNG alpha masks are transient view data, excluded from sidecars and PSD patches. A request counter prevents deferred pixel decoding from replacing a newer selection or gesture.
- `shared/psd-meta.ts` owns slice settings, identity checks, sidecar import/export and manual merge selection trees. Raw source hashes permit restoring identities only for the exact same imported bytes; changed files match scoped metadata IDs.
- Newly assigned/repaired GameFlow PSD layer identities use the same eight-character Nano ID allocator. Existing embedded PSD identities and native numeric IDs are not subject to prototype document migration.
- `shared/psd-binary.ts` bounds PSD v1 parsing and patches only layer `shmd/gflw` metadata. It preserves other tagged data, channels, image resources and composite bytes without reconstructing artwork through a general PSD writer.
- PSD decoding uses pinned `ag-psd` in a bounded, transient Worker, with OffscreenCanvas image encoding and a 30-second timeout. The bundle is inline and the Webview CSP allows `worker-src blob:`; UI assets stay local.
- The legacy `psdOutput` request remains a bounded explicit-output boundary. Dedicated PSD editors save their host-owned state directly; explicit PSD copies and native save-as patch only metadata and write a corresponding sidecar. Explicit copy leaves the original configuration dirty. Webview messages cannot choose arbitrary output paths.
- `shared/psd-export.ts` owns effective names, batch validation, resource-name conflicts and the versioned `gameflow-resources.json` schema. Optional `SliceConfig.exportName/shared` persist with sidecars and embedded metadata; legacy `name` remains preserved and does not silently become an export override. Default names use a btn/img prefix and layer initials, adding PSD initials only for nonshared resources; explicit export names override either default. Placeholder, conflict detection and output batches use this same naming rule. Directory resource names identify output files, while PSD document/layer IDs identify provenance. Shared exports replace same-name resources and transfer provenance to the generating PSD.
- `psdResourceExport` accepts only choose/export actions, request IDs and validated batches (at most 128 PNGs / 48 MB), never arbitrary paths. `PsdExportController` owns the native directory picker and workspace-state URI, rejects dirty target documents and serializes exports to the same directory within the process. Browser preview uses an explicitly selected File System Access directory; unsupported browsers report the limitation. Replies are isolated from prototype edit/save/history sequencing; typed resource conflicts map back to PSD tree rows.
- `shared/psd-export-directory.ts` validates PNG headers/dimensions, reads current provenance, plans the whole batch, and rechecks relevant filenames plus bytes before writing. PNGs precede the manifest commit; failed writes restore backups/remove newly created files where possible and report rollback failures. This is not an atomic transaction against independent external writers. Source ownership requires a persistent PSD documentId, restored from saved configuration when no embedded identity exists.
- Canonical nine-grid settings are `metadata.slicing.nineGrid`. The original sample's legacy `metadata.slice` is read only when `slicing` is absent; legacy and other unknown fields remain preserved, and new consumers must prefer `slicing`.

## Future Document Evolution

原型复合控件由 schemaVersion 3 引入；当前新文档和首次有效编辑使用 schemaVersion 5，v1/v2/v3/v4 仍可读取，普通读取保持内容。新增 radioGroup 类型、widget.skinNodeId 和 widget.optionNodeIds，旧版本拒绝这些类型/字段。共享 ui-parts.ts 校验皮肤的直接子级关系、Slider 无相对约束、Radio 成员有效性及唯一归组、空槽与选中索引；JSON Schema 约束字段类型、适用节点类型与文档版本。引用使用节点身份，复制/粘贴/整页复制及 Nano ID 迁移同时重映射，删除/换父级/转换在原事务中解除失效关系。派生皮肤位置与可见性不形成第二份文档权威。此变更不新增宿主协议、PSD 资源引用或 Prefab 写入入口。

此前 schemaVersion 2 引入类型化 layout/widget 字段；这些字段与原有 ID 在 v3 中继续保留。布局解算、编辑意图与字段验证分别由 shared/ui-layout.ts、ui-edit.ts、ui-config.ts 负责；DOM 只呈现解算几何。计算结果不是第二份文档权威。详细规则见 [11-prototype-ui-layout.md](11-prototype-ui-layout.md)。

The initial `CustomTextEditorProvider` and full-document edit are intentionally small. A future host session, fine-grained reducer or multi-view synchronization requires a new work-item spec when at least one is needed: concurrent Agent edits, multiple authoritative Webviews, independent history, external-change conflict resolution, or demonstrated whole-document performance problems. The v1 node model allows optional presentation fields (`style`, `imageData`, `hidden`, `locked`) and page background while keeping the TextDocument authoritative; the Webview does not accept remote image URLs or arbitrary commands.

## Canvas Reference Ownership

Schema v4 introduced `page.componentRootId` and `node.prefab: { source, documentId, pageId }`; schema v5 adds `instanceEdits: { overrides, additions }`. Empty source addresses the containing file; external paths resolve relative to that file. Canonical instances own placement and store deltas plus real additions, without cached source descendants. `canvas-instance-data.ts` validates whitelisted property paths and stable targets; address parts carry document/page identity, node ID and node/addition kind. Equality uses field tuples and is independent of JSON key order. Owned additions participate in ID validation, allocation, copy and migration; source IDs remain scoped to their definitions.

`canvas-instances.ts` composes the one tree used by canvas, layer tree, selection, Inspector and layout. Source roots alias instance roots; nested boundaries preserve ownership and variable scopes. Editing ordinary-looking composed nodes produces owned-node edits, property deltas or additions through one shared persistence boundary. Inherited deletion/type/parent/order changes are rejected centrally. Source changes can suspend incompatible overrides and leave missing-parent additions in a repair group, preserving serialized data. Bounds remain 64 source files, 24 nested layers and 5000 composed source/addition nodes. Local additions may reference the same source without being mistaken for a source-definition cycle; depth remains separately bounded.

`applyCanvasOverrides` carries a stable target and fields, or an exact `selections` list of target + fields for a multi-node choice, together with request ID, instance version and expected source fingerprints. Selection modes cannot be mixed; explicit lists must be nonempty, bounded, unique and still present in the stored overrides. Empty or stale selections reject the whole request and never mean apply-all. The host resolves registered dependencies, opens authoritative TextDocuments including dirty contents, checks identities/versions/read-only permissions, recomputes the plan, and submits source changes plus cleanup of only the selected local fields in one text-only WorkspaceEdit. Same-file changes merge first. Native VS Code grouped undo/redo and subsequent edits are covered by `npm run test:instance-host`. No implicit source save occurs. DocumentSession queues the action behind edits and accepts only its matching explicit completion; source watcher messages cannot acknowledge it. Deferred edits replay against the applied snapshot. Browser preview allows same-file transactions and disables external snapshot writeback.


`chooseCanvasSource`, `openCanvasSource` and `canvasSources` isolate source catalogs from authoritative snapshots. DocumentSession ignores source responses for edit/save/history sequencing. The per-editor host controller loads a maximum of 64 source files, includes dirty open TextDocuments, reads clean files from disk, watches changes/create/delete and refreshes nested dependencies with an epoch guard. Disposal releases watchers, subscriptions and pending timers. Selecting a legacy source completes the normal ID migration as an unsaved undoable WorkspaceEdit before exposing target IDs. Browser preview imports explicit File snapshots with separate localStorage persistence and an explicit reimport message; it cannot watch arbitrary disk paths. See [canvas-component-references.md](canvas-component-references.md).
