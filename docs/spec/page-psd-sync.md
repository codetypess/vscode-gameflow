# 页面原型与 PSD 的文字和结构同步

Status: Verifying

日期　2026-11-20

## 同步范围

策划与美术从同一个页面出发，各自增删控件、调整层级或改文案后，可以逐项合并。**原型始终用自己的内置资源绘制控件。** 同步页只比较两侧的文字内容与控件结构。PSD 预览可以展示实际美术画面，便于定位改动。[页面交互稿](../design/page-psd-sync.html)

| 改动 | 同步行为 |
| --- | --- |
| 修改按钮、标题等已识别文字节点的内容 | 显示上次、原型、PSD 三个文本值。采纳后只改目标文字内容，沿用目标侧的字体、字号、颜色和排版。 |
| 从 PSD 采纳字号 | 「PSD 同步」逐项比较文字和输入框的字号，可选用 PSD 字号或跳过。「PSD → 原型」固定采用 PSD 值。新增文字随结构一起采纳字号。 |
| 原型新增「帮助」按钮 | 在 PSD 对应父组和顺序处补可编辑的控件组及文案子层。初次生成所需的占位使用该控件内置资源。 |
| PSD 新增「公告」控件组及文案 | 识别为 UIButton 后可在原型同一父级创建按钮和文案子节点。复用编辑器的按钮默认值，包括内置浅灰按钮 `button/gray`。已有控件保留策划选定的内置资源。 |
| 已对应控件改名、删除、换父级或调整同级顺序 | 按控件身份显示一次结构变更。删除或移动含其他美术内容的父组时列明受影响后代，再由用户决定。只比较同级控件的相对顺序。 |
| 美术重画按钮、增加发光、蒙版、装饰或状态图，策划更换内置图片 | 同步项数为零。美术预览可显示新画面，原型按自己的内置资源绘制。即使图层数量、像素边界或切图配置变化，也无需登记逐项忽略决定。 |

首版将独立的位置、尺寸调整列为待确认的布局范围。新增控件可用已知控件布局框初始化位置、尺寸，现有控件仅因阴影或透明边界变化而改变的图层包围盒不参与结构比较。事件、跳转沿用原型编辑流程。

## 识别控件

- 现有生成器会写入原型文档、页面、节点和槽位身份，页面保存 PSD 绑定。同步按稳定身份对应**控件与文字节点**，跳过外观槽位及其整个美术子树。普通图层、装饰组和装饰内的文字不自动成为原型控件。已有的 PSD 切图、资源预览和 Prefab 导出各有入口。[页面绑定](page-psd-binding.md) · [公开组名与槽位](page-psd-layer-conventions.md)
- PSD 新增控件可通过明确的控件类型标记及已识别父级成为候选，例如登录页下的「公告 (UIButton)」。用户确认候选的类型、父级、文案及顺序后创建。首次关联普通 PSD 时可手动指定相应的逻辑节点。树内用于美术制作的文件夹和图层不参与控件层级排序。
- 新控件复用原型编辑器相同类型的创建规则和内置资源，并分配原型节点身份。同步记录维护结构对应关系。此操作无需生成切图、选择美术资源或给原型图片槽写入 PSD 资源引用。

### Photoshop 新增的可编辑文字

2026-11-26 复现：在页面根层添加名为「公告」、内容为「系统即将维护」的文字层。解码结果含完整文案，同步树却有零个节点。建树逻辑曾只在按钮下推断未标记的文字层。另一次独立读取也给这个无内嵌元数据的图层分配了不同的临时身份。

页面根层、页面包装组或已识别且可容纳子控件的组下，直接新增的可编辑文字按 UILabel 显示为结构新增。用户可以跳过，或将文案和相对位置采纳到原型。装饰组、皮肤槽、组件实例内部和列表项沿用已有遍历边界。

验收覆盖新增、跳过、采纳和重新比较。页面基线为无内嵌身份的文字记录同一 PSD 内唯一的原生图层编号，以便重读或编辑文案后认回同一节点。原生编号缺失或重复时，文件内容指纹和图层位置只对同一份文件内容有效。已确认的图层身份优先。

Chrome 在生产构建中读入真实 PSD，确认「公告」显示一项绿色新增，采纳后重开显示零项差异。重新读入修改过文案的文件后，同一控件显示一项文字修改。隔离副本补齐工作区中已删除的星海登录样例后，生产构建和 411 项共享测试通过。

### 从 PSD 采纳字号

2026-11-27，星海登录 PSD 的 `version` 文字层声明了 34 px。同步读取器只将文案交给比较树，新增节点沿用了编辑器的默认字号。已有节点的字号也未进入比较与写入。

「PSD → 原型」采用与 PSD 导入相同的首段文字样式，结合文字图层的变换换算画布字号，再按目标控件及祖先的缩放换算本地字号。一个原型控件保存一个字号。缺少可读字号时沿用目标样式。

验收覆盖新增文字、仅改字号、预演与确认、取消、保留其他文字样式，以及应用后重复同步显示零项差异。

Chrome 实测从「单向同步 → PSD → 原型」读入星海登录样例，确认应用后，`version` 节点的字号为 34 px，再次比较为零项差异。单向同步界面回归、414 项共享测试及生产构建通过。

普通「PSD 同步」曾直接比较仅含文案与结构的树，已有 `version` 即使字号不同也显示「0 项差异」。审阅窗与单向同步共用字号换算。旧基线缺少字号时展示双方现值，允许选择「把原型改为」或「本轮跳过」。只采纳字号写入原型和同步基线。同轮另有 PSD 编辑时，基线采用已校验的输出图层字号。验收检查跳过、采纳、预览、应用后重开及同轮双向合并。

Chrome 在星海登录样例副本中验证了旧基线的 `version`。普通同步窗列出 16 px 与 34 px 的一项差异，跳过后重开仍有一项，采纳后原型为 34 px，再次打开为零项。含其他 PSD 写入的同轮合并、四个单向操作、414 项共享测试及生产构建通过。

## 同步页

旧扩展宿主可以读取重建后的 Webview。用两个隔离的 VS Code 窗口从磁盘打开同一份星海登录页，旧宿主成功返回 21 个图层，但在协议校验时丢弃新界面的 `review` 请求，导致同步窗空等至三分钟超时。当前宿主约 1.1 秒返回比较结果，显示两侧预览和零项差异。

原生宿主生成 Webview 时标识其支持的同步协议。旧宿主下，窗口可展示该页面已加载的只读预览，提示重新加载 VS Code 窗口，并禁用应用。当前宿主仍在打开和应用时从磁盘核对绑定 PSD 与切图配置。浏览器预览沿用本次会话选择的文件。

同步窗宽高由编辑器可用区域和用户手动尺寸决定。窗口不显示独立缩放按钮，鼠标移到四条边或四个角时显示对应缩放指针，直接拖动边缘调整宽高。边缘命中区通过指针捕获跟随鼠标，拖动结束保存尺寸，重开恢复相同宽高。正常宽度使用节点树、棋盘背景双画板、属性详情三列；缩小宿主后依次纵向排列。树的展开、选中节点、切换当前与预计结果、打开应用明细和错误提示均只影响内部滚动区。底部操作固定可见。验收记录上述交互前后的外框，并实际拖动检查宽高变化。

1. 在已绑定页面的「更多」菜单打开「同步文字与结构」。左侧以共同基线、当前原型和当前 PSD 的逻辑节点并集组成完整页面树。每行显示节点名和已有变量名，可展开父子层级。保留未改节点作为上下文，缺失节点留在原父级和原顺序上。只有美术变化时仍可浏览整棵树，待处理数为零。
2. 选中变更后，中间双画板显示原型与 PSD 局部及「当前 / 同步后」。右栏复用预制体同步的属性值和单选交互，每项显示变动来源、双方现值和可展开的上次同步值。结构增删显示控件类型与层级路径，换父级显示两侧父路径。原型和 PSD 两个预览都可直接点击控件区域选中节点，并同步节点树、选中框和详情。重叠节点选当前绘制顺序的最上层，已删节点的虚线位置仍可点击。原型预览的当前与预计状态都使用内置资源。
3. 单边改动给出方向建议，双方改同一字段到不同值须选择来源或本轮跳过。原型新增「帮助」、PSD 新增「公告」可在一轮里分别采用。删除与编辑相遇、重名、身份重复或移动存在依赖时单独确认。
4. 预演按目标列出原型与 PSD 将收到的编辑，打开、比较和取消均为只读。无文字和结构差异时无需应用。仅发生美术变化时也无需重建基线或生成 PSD 副本。

右栏的「对应已有 PSD 图层」在未匹配的原型控件上提供独立的选择区。图层按 PSD 层级展示，选中后显示完整路径。已对应到现存原型控件的图层、资源槽与不参与结构同步的分支不能选。已有组可作为路径保留。确认关联后重新比较，并在本轮应用时保存对应关系。浏览器验收覆盖冲突、推荐方向、键盘选择、图层树定位、取消或确认关联、应用后重开和窄窗滚动。

### 差异颜色与定位

- 参照上次同步的共同基线，新增标绿色「+」，删除标红色「−」，改文字、改名或移动等修改标黄色「~」。双方文案冲突仍用黄色，详情显示「待决定」及两个当前值。来源用「原型 / PSD」文字说明。选择框、跳过和折叠状态独立于差异颜色。
- 点选树节点联动两侧预览。在有效位置显示相同的颜色和符号。对已消失的节点，在原位置显示带「−」的虚线轮廓，作为差异标记。当前与同步后预览分别对照同一基线，采纳、恢复、跳过均可检查两边结果。
- 新增的整棵控件子树按一个决定计数。展开节点可看到内部文案及变量名。改动的子节点默认可见，未改的分支可手动展开。移动记录新旧路径，保留节点身份。

## 基线与写入

画布组件实例以单个节点参与页面比较。普通 PSD 组件组可以在审阅时转换为嵌入式智能对象。智能对象缺少原型新增图层时，审阅在该节点提供「补入智能对象」，并预演合并后的美术图。现有内嵌图层的美术编辑在 Photoshop 中完成。[PSD 组件智能对象](psd-component-smart-objects.md)

绑定了组件源 PSD 的实例可在审阅中更新内嵌文档。双方均有修改时可选择更新或保留父 PSD 的内嵌内容。[组件源 PSD](psd-component-sources.md)

首次生成并绑定时记录双方的文字和控件树，按原型文档、页面、PSD 文档隔离。每个逻辑节点记录身份、类型、名称、文字、父级及兄弟顺序。文件指纹用于发现审阅过期，业务差异由这些字段决定。已有 PSD 缺少基线时先确认对应关系，此时仅描述「仅原型存在 / 仅 PSD 存在」。同名、图层序号或相似像素不足以推断同源。

与上次已协调的值分别比较。双方修改不同字段可以合并，同字段异值由用户取舍。已完成的字段推进基线，跳过的字段下次继续显示。新控件和文案子节点一起登记，重试和再次同步都只产生一个实例。

修改 PSD 时，从当前美术稿预演选中的文字和结构变更，校验其余内容的保真性。保存时默认定位到当前绑定的 PSD，经保存对话框确认后写回原路径。选择新文件名会创建副本并更新页面绑定。提交前复核原稿、切图配置和页面版本。覆盖是磁盘保存操作，GameFlow 的编辑器历史记录原型编辑和同步基线。无法可靠写出的变更可以跳过，独立的原型侧操作仍可完成。

## 同步保存与覆盖

原生保存对话框可以返回已存在的路径。确认应用时选择已绑定的星海登录 PSD，宿主的无覆盖改名返回 `FileExists`，同步窗口显示底层文件系统错误。

保存对话框默认使用页面绑定的 PSD。确认覆盖时使用已验证的同步内容替换该文件，同时更新现有切图配置的源指纹与图层列表。配置写入失败时恢复 PSD。存在未保存编辑、其他编辑会话占用或源稿已变化时，宿主终止覆盖。另存时已有文件进入重选流程，选择未占用的新文件名后写出副本。取消保留预演。

验收覆盖确认覆盖、取消、源稿变化、切图配置更新失败、同名路径的 Windows 大小写差异、另存目标冲突，以及星海登录页覆盖后重新比较为零项差异。

真实 VS Code 在星海登录页样例的临时副本上完成取消与同路径覆盖。覆盖后只有原 PSD 路径，切图配置指纹与写入内容一致，重新比较为零项差异。生产构建和 397 项共享测试通过。
