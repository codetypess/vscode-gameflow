# Canvas Instance Editing

Status: Done
Date: 2026-11-17
Scope: 画布引用实例展开、属性覆盖/还原/应用到源、局部附加节点和继承结构保护

本文扩展 [canvas-component-references.md](canvas-component-references.md) 的整体引用模型。用户已确认实施；schema v5 和共享组合树替代原子引用，编号基线同步记录持久化、编辑与宿主事务边界。

## 1. Context

当前“公共提示卡 A / B”可以引用另一模块的同一画布，但图层树只显示实例根，无法展开修改内部文案，也无法在实例内增加业务节点。用户要求引用实例像普通节点一样展开编辑、允许附加节点，同时限制删除源节点，并参考 Laya 的 Prefab 机制。

受影响的基线是 [01-product-workspace.md](01-product-workspace.md)、[10-extension-architecture.md](10-extension-architecture.md) 和 [11-prototype-ui-layout.md](11-prototype-ui-layout.md)。这些基线随实现同步。

## 2. Goals

- 引用实例显示可展开的组合层级，复用普通节点的选择、属性面板、布局和新增入口。
- 图层树以专色区分引用实例/继承节点与本地普通节点，局部覆盖另加标记，参考用户提供的 Laya 层级树效果。
- 修改源节点的实例属性只影响当前实例；未覆盖属性继续跟随同文件或跨文件源组件。
- 属性面板标出局部覆盖，右键支持还原为源值及应用选中属性到源组件；跨文件应用保留现有源编辑并支持关联撤销。
- 实例可以向合法容器附加普通节点或引用实例；附加节点保留正常的编辑和删除能力。
- 继承节点不可在实例内删除、剪切、改变类型或改动继承结构，所有操作入口执行同一保护规则。
- 保存、刷新、复制实例、源更新、嵌套引用及撤销重做保留身份、覆盖和附加内容。

## 3. Non-Goals

- 本期不提供 Prefab 变体、解包引用或继承节点删除标记。
- 应用到源的范围为属性覆盖；本期不把实例附加节点、重排或其他结构差异提升到源组件。
- 本期不允许实例重排或换父继承节点；可通过局部隐藏代替删除。
- 不改变“存到画布”只接受合法普通 UIBox 的类型边界。
- 本方案不实现 Laya 文件导出或外部 Prefab 回写；相关资产流程仍由 [prototype-layaui-prefab-psd.md](prototype-layaui-prefab-psd.md) 负责。

## 4. Current Behavior

- v4 引用保存 `prefab: { source, documentId, pageId }`，实例根拥有独立位置、尺寸、变换、名称、显隐、锁定及可选透明度。
- `projectCanvasReferences` 仅为渲染展开源节点，生成不持久化的 `@reference:*` ID；所有子节点命中归属整个实例。
- 图层树只读取当前文档的真实节点；`canHaveChildren`、作用域和验证均禁止引用节点接收子节点。
- 选择、层级编辑、剪贴板和控件引用大多使用同页普通节点 ID。只放开树展开或 `canHaveChildren` 会造成编辑写回、身份和删除保护不一致。
- 宿主已加载跨文件依赖并监听未保存源修改；浏览器仍使用用户导入的源快照。

## 5. Proposed Behavior

### 5.1 展开与选择

引用实例根代表源根，不再额外显示一层重复的源根。示意：

```text
公共提示卡 A                 [引用实例]
├─ 提示文案                  [来自源组件；局部覆盖时显示标记]
└─ 关闭按钮                  [本实例附加]
   └─ 按钮文案               [本实例附加]
公共提示卡 B                 [同一源的另一个实例]
```

- 沿用默认收起规则，展开箭头展示组合后的子树；折叠和展开只改变视图。
- 树中选择继承子节点后显示其正常属性，并标出源组件、属性继承/覆盖状态及禁用原因。搜索和选中定位包含组合节点。
- 普通画布单击保持逐层选择；双击实例进入实例作用域，继续双击可以钻入内部容器。直选模式可以直接命中实例内部节点；树展开状态不影响命中。
- 面包屑包含实例和内部编辑层；返回操作与普通容器一致。源失效时保留实例选择及本地数据的管理入口。

#### 引用归属的颜色与标记

参考用户提供的 Laya 层级树截图，引用相关节点的名称及类型图标使用统一的引用专色；深色主题优先青绿色，浅色主题使用对比度合适的深青色。

| 节点身份/状态 | 图层树显示 |
| --- | --- |
| 引用实例根，包括本实例附加的另一引用实例 | 引用专色，并保留引用图标；本实例附加的引用图标右下角叠加“+” |
| 来自源组件的继承节点 | 引用专色；来源在属性面板查看 |
| 有局部属性覆盖的继承节点 | 保持引用专色，附加独立的覆盖圆点/标记 |
| 本实例附加的普通节点及其普通子节点 | 普通节点颜色，类型图标右下角叠加“+”标记 |
| 普通页面中的非引用节点 | 保持普通节点颜色 |
| 缺失、失效或待挂接目标 | 保留归属识别，另用诊断图标/提示表达异常 |

- 颜色由组合模型中的引用身份和来源归属决定，不通过父元素颜色继承。处于引用实例内部的本地附加普通节点仍使用普通色；附加节点本身如果是引用实例，则使用引用专色，其源子节点也按继承节点着色。
- 局部覆盖不会把源节点改成本地普通节点颜色；还原覆盖只移除覆盖标记，来源身份保持不变。
- 选中/悬停背景沿用编辑器主题，选中后仍应识别引用专色；搜索命中、隐藏、锁定状态不能把来源和覆盖状态完全遮蔽。使用主题语义色并检查深浅及高对比度主题的可读性。
- 引用图标、覆盖标记、属性面板来源信息和可访问名称共同表达身份，颜色不是唯一提示。图层节点名称不显示拼接名称、来源路径、变量及操作说明的悬浮提示；引用失效时提供独立诊断状态。
- 这是图层树的编辑器表现，不写入节点 `style.color`，也不改变画布中文字、图片或其他内容的颜色。

### 5.2 操作权限

所有允许操作继续遵守锁定、容器能力、布局管理轴、皮肤部件和绑定校验规则。

| 操作 | 源组件继承的节点 | 本实例附加的节点 |
| --- | --- | --- |
| 展开、选择、查看属性 | 允许 | 允许 |
| 改文字、样式、图片、布局、位置和尺寸 | 允许，写入局部覆盖 | 正常修改 |
| 改显示名、变量、显隐 | 允许，写入局部覆盖并校验变量 | 正常修改 |
| 在容器中新增或粘贴子节点 | 允许，生成本实例附加节点 | 按普通容器规则 |
| 删除、剪切 | 禁止；提示“源组件节点不能在实例中删除，可隐藏或编辑源组件” | 允许，服从现有绑定保护 |
| 换父、同级排序 | 禁止改动源结构 | 同一所属实例内允许 |
| 改节点类型、替换引用源、存到画布 | 禁止改变源身份/定义 | 按原操作类型、锁定和绑定边界规则 |
| 复制、生成副本 | 允许生成局部快照副本，明确标为附加节点 | 沿用普通复制规则 |

本层拥有的整个实例仍可删除，包括本层附加的引用实例；删除只移除该实例和其局部数据。源组件继承的嵌套引用根属于继承节点，不因它也是一个引用就获得删除权限。

多选含受保护节点时，Delete、剪切和结构修改整笔拒绝，并给出原因，不静默处理其中一部分。删除普通父容器或本层拥有的整个实例可正常连带删除其中的引用；这是删除拥有者，不是删除实例内部的源节点。

### 5.3 属性覆盖与还原

- 修改继承节点时记录字段级覆盖，其他属性继续继承；拖动、缩放、方向键和约束编辑共用普通节点的逆向布局计算，再把结果转为覆盖。
- 可覆盖普通内容、外观、布局及有效控件设置；`id`、`type`、结构父级、源引用身份属于保护字段。不能用 `locked: false` 覆盖绕过源锁定。
- 实例根已有独立身份、位置、尺寸等继续以现有实例字段为准，不在覆盖表重复记录。可选根透明度保持现有优先级；根外观、Padding 等新增可编辑项存覆盖。
- 字段显示覆盖标记，提供“还原此属性”；节点提供“还原该节点覆盖”；实例提供“还原全部源属性”。还原会删除对应覆盖项，重新继承当前源值。
- “还原全部源属性”只清除本层源属性覆盖，保留实例独立布局和附加节点；附加节点的清理使用独立删除操作。
- 已显式覆盖为当前源值的字段仍保留覆盖标记，直到用户还原，避免下一次源更新意外改变实例。
- `null`、空串、0、false 均是有效设值；“删除可选属性”和“删除覆盖以继承”是不同动作。

例如只把 A 的提示文案改为“领取成功”，B 仍继承原文；随后源组件调整背景和默认文案，A/B 均更新背景，B 更新文案，A 保留“领取成功”。A 还原文案后立即使用源的最新文案。A 的附加关闭按钮始终只属于 A。

#### 属性面板的修改标记与右键菜单

引用来源区参照 Laya 收成单行：左侧源组件名链接，右侧“编辑”与“覆盖属性”入口。来源区下方以主题细横线与名称、变量等普通属性分隔。正常状态不显示边框卡片、标题、源页面 ID、常驻说明或一排还原/应用按钮；完整来源路径与归属说明置于悬停。失效来源保留紧凑异常提示及详细原因。

“覆盖属性”默认展开双栏浮层：左栏为当前实例有修改的节点，右栏为活动节点的具体属性覆盖及源值→本地值，可逐项勾选。允许跨节点保留勾选，初始全选，可整节点/全部切换；底部“还原所选”“应用所选”仅处理明确勾选的地址+字段。几何/范围关联字段自动成组勾选并说明，不隐藏附带字段。浮层本身呈现目标源和差异，点击应用无需再次弹同样清单；原有字段右键及其差异确认保持。无覆盖显示空状态，零选择和不可写/无效源禁用应用并说明，空选择不能解释为全实例。请求携带非空且无重复的目标/字段选择，宿主重新验证并用单笔原有多文档事务提交；只清理选中覆盖，未勾选覆盖及附加节点保留。还原同样只形成一笔文档事务，不改变持久化格式。

参考用户提供的 Laya 属性面板截图，在有本层覆盖的属性行左侧显示细竖线/标记，并为实际覆盖的字段显示独立标记。标记不占用额外行，不因出现/消失改变输入框对齐。图层树的引用专色表示来源，属性行标记表示本层修改，两者独立。

- 例如“尺寸”一行仅 W 有覆盖时，行上出现标记，W 显示覆盖状态，H 继续显示继承状态；不能把整行的全部字段视为都已修改。
- 属性行和字段不显示包含覆盖字段、本地值、源值及来源路径的长悬浮提示；差异与来源通过“覆盖属性”浮层查看，右键操作保持。明确设置但与源相等的值仍属于覆盖；不是按数值是否相等临时推断标记。
- 属性面板和图层面板屏蔽无操作区域的浏览器默认右键菜单；属性标签/标记支持右键和键盘菜单，提供“还原此属性为源值”和“应用此属性到源组件「名称」”；菜单/提示标明目标文件。同组/节点另提供“还原本组/本节点覆盖”和“应用本组/本节点覆盖到源组件”。实例汇总入口可选择全部属性覆盖。
- 单字段动作仅处理该字段；分组/节点动作显示包含的覆盖字段。几何、约束、尺寸模式等存在耦合时，预先列明必需的关联字段并作为一个操作处理，不隐式携带无关字段或提交非法布局。
- “还原”读取当前下一层源有效值，不回退到最初修改前的历史快照；Ctrl+Z 才是历史撤销。还原完成后对应标记消失。
- 实例根原有独立位置、尺寸、名称等不是本方案的继承属性覆盖，不提供误导性的应用菜单；提示其属于实例独立属性。普通节点及本地附加普通节点继续使用普通属性编辑，不显示源覆盖菜单。
- “应用”在没有本层覆盖、源失效/不可写、源锁定或不能合法映射到源时禁用并说明原因。“还原”只要求本实例可编辑且存在对应覆盖；源不可写不妨碍还原，源缺失时仍可删除本地覆盖以放弃该修改，并提示暂时无法预览源值。

### 5.4 应用属性到源组件

“应用”把选中的局部属性覆盖提升到其源定义，成功后清除当前实例中已提升的对应覆盖，当前显示值保持一致。其他实例未覆盖的属性立即跟随新源值，已有本地覆盖的实例保持各自的值。失败、冲突或取消时不清除本地覆盖。

例如 A 的文案覆盖为“领取成功”，右键该字段选择应用到公共提示卡：公共源的提示文案变为“领取成功”，A 的文案覆盖标记消失，B 若没有文案覆盖也同步更新；A 的附加关闭按钮及其他属性覆盖保持不变。之后撤销这次应用，应一起恢复源原文案和 A 的本地覆盖。

- 单属性菜单直接标明目标组件，提示可影响其他未覆盖实例；用户可查看源当前值与拟应用值。分组/整实例入口展示待应用字段和目标来源。只报告已加载、可确定的受影响引用，不把已知计数描述成全工作区完整统计。
- 嵌套引用默认应用到当前实例直接引用的源定义。若目标节点在该源定义的嵌套引用中，就修改该源定义拥有的嵌套实例覆盖；不自动穿透并修改最深公共组件。菜单显示实际目标层和文件；若要修改更深层组件，显式进入相应源组件后操作。
- 来源和实例同文件时，在一次文档事务中更新源目标及清理实例覆盖；跨文件时通过宿主一次多文档文本编辑完成两者，使用同一撤销/重做单元，不连续发送两次无关联编辑。
- 应用基于源最新 TextDocument，包括已有未保存修改；只修改选中属性及必要依赖，保留源中其他修改。源文档按正常编辑进入待保存状态，不隐式保存整份源文件，界面提示“已应用到源组件，源文件待保存”。
- 应用前检查源身份、节点地址、字段合法性和文档版本；源在查看/提交期间变化时刷新差异并要求重新执行明确的应用动作，不使用旧整份文档覆盖新内容。
- 若某个控件属性引用当前实例附加节点，而源中没有对应目标，就不能单独应用该属性；给出具体原因，保留覆盖。批量应用任一字段不能合法完成时，整次拒绝，用户可单独选择其他字段；不静默部分成功。
- 清理仅针对本次操作实例的选中覆盖；同源其他实例的本地覆盖即使与新源相等也继续保留。附加节点、实例独立布局和结构保护不受应用动作影响。
- 浏览器预览支持同文件源的应用；外部导入快照不能写回原磁盘文件，该入口禁用并说明需在 VS Code 中操作，不伪装成已修改真实源文件。

### 5.5 附加节点与顺序

- 新增、粘贴、拖入到继承容器时，生成拥有独立 8 位 Nano ID 的附加节点；不写入源文件，也不将其持久化父级设为临时投影 ID。
- 附加节点可以挂在实例根、继承容器或同一所属实例的附加容器中；叶子节点不能接收子节点。源自其他模块的组件遵守相同规则。
- 附加节点可在同一所属实例中移动、排序、复制、删除；跨独立实例的移动/剪切暂不开放，可用复制粘贴创建新本地副本。
- 排序保存稳定的“插在某个同级节点之前”锚点，缺省为末尾；源节点相对顺序始终由源定义决定。多个附加节点使用记录顺序稳定排序。
- 锚点消失但父级仍有效时，附加节点临时排在该父级末尾并显示可修复提示，保留原锚点；用户重新排序会明确写入新锚点。
- 父目标消失或不再接收子节点时，保留附加子树并列入实例下的“待重新挂接”诊断组。该组不是布局节点，不把内容偷偷挂到实例根；提供重新挂接、复制、删除。画布在实例上显示诊断，未挂接内容不参与布局。

### 5.6 源更新与异常

| 源变化 | 实例结果 |
| --- | --- |
| 修改未覆盖属性 | 使用源最新值 |
| 修改已覆盖属性 | 保留当前实例覆盖 |
| 新增子节点 | 自动出现为继承节点 |
| 节点改名、在同一定义内移动且 ID 不变 | 覆盖继续命中；附加子节点继续随其父节点 |
| 删除覆盖目标 | 保留覆盖数据，显示失效目标；不误作用于同名新节点 |
| 删除附加节点的父目标 | 保留附加内容，进入待重新挂接状态 |
| 类型变化导致字段/绑定/子级不兼容 | 暂停不兼容部分并诊断，保留原数据 |
| 源文件丢失、身份不符、循环或超限 | 保留实例及局部数据，显示现有来源诊断 |

同名新节点不继承旧 ID 的覆盖；源目标以原身份恢复后可重新解析。跨引用边界搬移源节点导致地址变化时显示失效目标，不根据名字猜测目标。当前文件内的源删除可提示已知依赖影响；不承诺扫描所有其他文件，也不拦截用户直接编辑外部 JSON。

## 6. Design

### 6.1 借鉴 Laya 的范围

已核对本机 LayaAir 3.2.7 源码（commit `2c621a5f5`），目录 `D:/Users/bite/Desktop/github/LayaAir`：

- `src/layaAir/laya/loaders/HierarchyParser.ts:61`：`_$override` 以源 ID 或嵌套 ID 路径定位节点；`:88` 的 `_$prefab` 创建源引用。
- `src/layaAir/laya/loaders/SerializeUtil.ts:173`、`:200`：整理并应用多层覆盖；`:293` 用 `_$parent` 表达附加节点，配合 `_$index` 插入。
- `src/layaAir/laya/loaders/HierarchyParser.ts:247`：把附加节点挂接到源目标；目标缺失时引擎回退到实例根。
- `src/layaAir/laya/loaders/SerializeUtil.ts:336`：普通嵌套属性合并，数组与资源/引用类值整体替换。

GameFlow 借鉴“源定义 + 属性覆盖 + 附加节点”的组合方式，采用稳定同级锚点替代纯数字下标；父目标缺失时显式保留待挂接数据。图层树专色、属性行修改标记及还原/应用的交互参考用户提供的 Laya 编辑器示例。上述引擎代码不证明 Laya IDE 的删除权限或跨文件历史策略；继承节点删除保护和应用事务语义是本方案明确规定的 GameFlow 规则。

### 6.2 持久化与稳定地址

由 schema v5 承载：保留 `prefab` 来源字段，在引用节点上增加可选 `instanceEdits: { overrides, additions }`。它存差异和真实附加节点，不保存展开后的源子树。字段名已由共享类型与 JSON Schema 固定。

- `overrides`：每条包含稳定目标地址、字段 `set` 和 `unset`。没有字段记录表示继承；`set` 可写入显式 null；`unset` 表示实例主动移除可选属性；还原则删掉 set/unset 项。
- 覆盖按已知属性路径验证；嵌套普通对象按合法字段覆盖，数组、图片和控件引用整体替换。禁止同一路径同时 set/unset，禁止身份、结构和未知字段，不允许任意对象路径写入。
- `additions`：每个记录保存真实节点内容、稳定 parent 目标和可选 before 锚点。真实节点内容不同时保存另一套 `parentId`，避免双重结构来源；其子级也用附加记录描述。附加引用可以拥有自己的 `instanceEdits`。
- 所有本文件拥有的附加节点参加现有文档级/会话级 Nano ID 保留、冲突校验及复制重映射；继承 ID 只属于定义，不混入当前文档的普通 ID 空间。
- 地址包括当前实例上下文、每一层引用边界、定义身份和目标节点稳定 ID，明确区分定义节点、内层定义的附加节点与当前实例附加节点。路径段须携带所属层，不能仅把多个范围的 nodeId 扁平拼接。
- 当前实例根使用明确 root 地址；源根映射到实例根，普通页面的合成根也使用稳定 root 标记。禁止把 `@reference:*`、节点名、路径字符串名或数组索引写入目标地址。

单层示意：A 的覆盖命中 `(demoref1 → gameflow-shared-components / 7x5404qh → cardtext)`；B 命中相同源节点时外层实例是 `demoref2`，两者互不影响。嵌套引用再增加带来源身份的引用边界段。

### 6.3 组合模型与写回

新增共享组合层，输出布局/渲染树、稳定编辑地址、来源/所有权、源值/有效值、能力和诊断。画布、层级树、属性面板、作用域和引用选择器使用同一组合结果；临时渲染 ID 只作为显示层映射。

普通局部编辑命令先解析地址和能力，再选择写入当前文档的普通节点、实例属性覆盖或附加节点。源投影对象永远不直接作为编辑文档提交。新增到深层继承容器的节点属于当前可编辑实例，不反向写入内层源文件。只有显式的应用命令可以在合法目标源定义中更新属性，同时清理操作实例的相应覆盖。

复合优先级为：最深源定义 → 内层定义已有的实例编辑 → 外层定义的实例编辑 → 当前实例编辑；各层局部编辑修改自己拥有的真实数据。最外层有效覆盖获胜，实例根已有独立字段按既有规则最后应用。还原当前层覆盖后暴露下一层有效值；应用则把选中值提升到明确的直接源定义层。

几何覆盖和附加节点先组合，再使用现有共享布局解算，保持流式容器、约束和控件部件几何一致。编辑仍使用现有的坐标逆算和单次事务提交规则。

### 6.4 能力、控件引用与剪贴板

- 集中计算 `canEditProperty / canAddChild / canDelete / canReparent / canConvert / canRevertProperty / canApplyProperty` 等能力与原因；菜单、Delete/Backspace、剪切、拖动、工具栏、转换、还原/应用、直接命令及共享文档变更验证共用规则。不能只禁用右键菜单。
- 对普通编辑事务校验前后所有权差异；显式删除实例/普通拥有者和继承结构编辑是不同命令。来源缺失不应导致删除保护失效；原始文件文本被用户改写仍按合法数据解析，不将历史来源推断成新结构。
- 皮肤、Radio 成员等引用通过带作用域的目标地址解析到组合树，再映射到布局/渲染 ID；不把投影 ID 存回 widget。已有源内绑定保持源作用域，局部覆盖引用和附加节点引用可以指向所属组合实例内的合法目标。
- 不扩展页面普通节点与引用内部节点之间的任意跨边界绑定；源节点类型、皮肤部件角色、同级/从属约束与受控几何仍按已有规则验证。
- A/B 的继承变量分别在各自实例作用域内解析，不因相同源变量而构成页面重名；附加变量在所属实例作用域内检查，嵌套实例建立子作用域。页面普通节点和真实实例根的变量仍遵守现有页面唯一规则。源更新引入冲突时诊断，不静默重命名。
- 复制整个本层实例保留来源、覆盖和附加内容，重新分配全部本层拥有的 ID 并重写内部地址/绑定；源 ID 不重分配。
- 复制继承子树明确产生当前显示内容的普通快照副本，生成本地 ID。遇到嵌套引用边界保留其引用及有效实例编辑；跨复制边界绑定沿用现有拒绝规则，避免悬空绑定。剪切继承节点始终禁止。

### 6.5 应用计划与多文档事务

- 共享纯函数根据最新源和实例计算 ApplyPlan：选中属性、必要依赖、源写入位置/旧值/新值、本地待清理覆盖、绑定映射和验证结果。直接源中的普通目标写真实节点；嵌套继承目标写该源拥有的引用实例编辑；源中附加目标写其真实附加记录。
- 应用不是覆盖整个源投影。请求携带稳定实例/节点地址、字段选择、来源版本或内容指纹和 requestId；宿主从已登记的引用来源解析 URI 并读取权威 TextDocument，重新计算/验证计划。Webview 不能指定任意磁盘路径、命令或未验证的源文件正文。
- 使用带预期版本的文本编辑及单次 `WorkspaceEdit` 提交源修改与本地清理。同文件两种修改先合并到同一候选文档；不同文件各生成一次候选编辑。语法、身份、布局和引用验证全部通过后才提交；版本失配、只读或应用失败时不清理覆盖，禁止先成功一边再声称完成。
- 目标源和实例的待提交编辑需先完成同步，再执行应用。DocumentSession 为此增加显式动作请求/确认和关联操作 ID；事务期间更新派生视图时不能用一次 source watcher 响应代替操作完成，也不能把旧队列候选重放覆盖刚应用的内容。
- 多文档 undo/redo 必须验证能一并恢复源属性和本地覆盖，且不吞掉两个文件已有的历史。将 TextDocument 版本检查、部分失败防护、正常编辑/原生撤销与应用的排序列为宿主实现验收门槛；不能仅因调用一次 API 就声称已满足。
- 浏览器同文件应用复用一笔本地文档事务；外部源无写回命令。导入快照仍只作为来源视图，不成为可任意修改真实文件的权限。

### 6.6 源目录、历史与迁移

- 沿用现有源目录、相对路径、未保存文档优先和 watcher epoch；同文件及跨文件共享组合逻辑。源响应只更新派生视图，不生成实例文档历史或保存编辑。
- 一次拖动、一批新增、一次删除或一次还原各形成一个可撤销事务；附加节点删除不得留下本层悬空地址，绑定保护在事务前检查。
- 显式应用动作按上一节创建源与实例的关联编辑历史；后续 watcher 更新仍只刷新派生视图，不重复生成编辑或自动清除其他实例的覆盖。
- v1–v4 继续读取；旧引用按空编辑层解释，普通读取不补写数据、不重新分配 ID。首次有效编辑时按现有版本升级事务规则进入 v5，可撤销。
- 保留现有 64 源文件、24 嵌套层和 5000 投影节点限制；附加内容计入组合展开预算，超限只产生派生诊断，不裁剪真实持久化数据。最终类型实现须明确区分可离线验证的持久化结构和依赖源目录的组合语义诊断。

## 9. Acceptance Criteria

- A/B 可展开并独立选择子节点；普通选择、直选、树和面包屑对应同一稳定编辑目标。
- 引用实例根和继承节点有区别于普通节点的图层树专色；本地附加普通节点保持普通色；局部覆盖标记独立于来源颜色，主题和选中状态下仍可辨认。
- A 可以覆盖源文案并附加按钮；B 不出现 A 的局部改动；源未覆盖属性继续同时更新两者。
- 继承节点在全部删除、剪切和结构编辑入口中受保护；多选拒绝行为一致；本地节点及整个本层实例仍能正常删除并撤销。
- 挂接到合法继承容器的本地节点在保存刷新和源节点改名/移动后保持附加关系；失效父目标保留数据并能重新挂接。
- 单属性、单节点、全实例还原有明确作用范围，不意外删除附加节点或重置实例独立位置。
- 属性面板在实际覆盖的行/字段显示标记；右键和键盘菜单支持还原或应用指定属性，能清楚识别目标源及操作字段。
- 引用区保持紧凑单行；覆盖属性默认双栏，支持跨节点逐字段勾选及还原/应用所选，空选择不会变成全实例操作，窄窗口不溢出视口。
- 应用 A 的文案到源后，源和无文案覆盖的 B 更新，A 仅清除此文案覆盖；其他本地覆盖和附加节点保持。一次关联撤销/重做同时恢复/重做源修改和本地覆盖清理。
- 应用保持源其他未保存修改；源失效、只读、并发冲突或目标字段不合法时保留覆盖且不产生单边成功。嵌套目标应用到明确的直接源层；浏览器不误报跨文件磁盘写回。
- 嵌套和跨文件引用不串 ID、覆盖或控件绑定；源异常和组合超限保留真实数据并显示诊断。
- v4 示例无编辑打开不改内容；v5 保存重开与 undo/redo 保留实例关联、覆盖、附加节点及身份。
- 自动化、构建和实际交互验收有对应结果记录后，才更新状态与编号基线。

## 10. Risks and Rollback

组合树将改变普通单页 ID 假设，选择、拖动、控件引用和剪贴板必须一起迁移到地址/能力模型，不能先开放结构写入再补保护。源定义变化可能使局部编辑失效，保留原数据与诊断优先于猜测修复。跨文件应用新增多文档编辑与关联历史要求，必须验证同步队列和版本冲突处理。继承结构不可重排、跨实例剪切及附加子树提升到源暂不开放属于明确的首期能力边界。

旧版本不理解 v5；实现时使用版本校验明确拒绝，不提供会丢失覆盖/附加节点的降级保存。升级前保留原文件；升级、本地编辑及显式应用都进入对应正常/关联历史。源的其他独立编辑不会因还原实例属性而回滚；跨文件应用通过其关联撤销单元恢复，历史冲突不能自动覆盖用户后续编辑。
