# Page Export Name

Status: Implementing
Date: 2026-11-17
Scope: 页面导出名称的编辑、保存及后续 Prefab 生成元数据

## 1. Context

页面目前只有显示名称和稳定 ID。用户要求在“页面名称”下方、“基础属性”上方插入独立的“导出名称”，供后续生成预制体使用。

## 2. Goals

- 四种页面根均可编辑独立导出名称，一行一个属性，与其他输入框对齐。
- 字段随页面保存、重载、复制和历史操作保留，独立于显示名称和 ID。

## 3. Non-Goals

本次不生成预制体、不写导出目录、不增加控件导出名称，不推断文件名或程序变量名。

## 4. Current Behavior

属性面板使用共享 Field 处理草稿及提交，页面修改通过 editCanvasPage 和既有文档事务保存。页面根属性采用可选 v2 字段，首次编辑由既有会话升级到当前版本。

## 5. Proposed Behavior

- 仅页面属性显示“导出名称”，紧接“页面名称”。初始为空；旧文档不自动填充。
- Enter 或失焦提交，Escape 恢复已保存值。提交时去除首尾空白，保留大小写及内部文本；留空移除持久化字段。
- 页面显示名称、ID、根类型及几何不因导出名修改而变化；显示名称修改不联动导出名。整页复制保留导出名称。

## 6. Design

新增可选 v2 `page.exportName: string`。设置后须为非空白字符串，与现有名称字段规则一致；共享模型、解析、宿主消息及 JSON Schema 同步校验，v1 拒绝该字段。不预设未来导出器的命名或冲突策略。

复用 Field 及现有页面事务。清空时显式传入 undefined，让 editCanvasPage 的页面属性合并覆盖旧值；JSON 序列化后不保留字段。

## 7. Implementation Plan

1. 扩展页面类型、共享校验与 JSON Schema。
2. 在指定位置增加复用的属性行。
3. 验证持久化、边界、复制及清空，更新基线。

## 8. Testing Plan

自动测试覆盖四种页面根的往返和协议接受、旧文档缺省、非法类型/空白及 v1 拒绝、页面复制、经真实页面编辑路径清空已有值。浏览器验证位置/对齐、Enter/失焦/Escape、撤销重做及保存重载。

## 9. Acceptance Criteria

- 页面名称下方可见且仅有一行“导出名称”，控件属性无此行。
- 名称独立保存，清空后 JSON 无 exportName，旧文档仍可打开。
- 共享测试、生产构建和浏览器验收通过。

## 10. Risks and Rollback

未来导出器需单独定义文件命名及冲突规则。本次仅增加可选元数据，可通过移除字段及对应属性行回退，不修改既有页面身份。
