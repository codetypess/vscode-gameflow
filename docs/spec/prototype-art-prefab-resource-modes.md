# 原型、美术 PSD 与预制体资源模式重设计

Status: Verifying
Date: 2026-11-18
Scope: 原型画布的三种资源显示模式、内置占位资源、UIButton 三态图片、UIBox 背景图片、Radio/Checkbox 与 Slider 图片、ProgressBar 横向/圆形模式及 PSD/Prefab 资源映射与输出。

## 1. Context

当前原型节点主要通过 `style.fill`、`style.borderColor`、`style.borderWidth`、`style.radius` 等字段直接绘制低保真外观。用户希望改为真实图片资源驱动：原型阶段使用内置按钮和色块，美术阶段装载 PSD 生成资源，预制体检查阶段装载已经导出的磁盘资源。三种模式复用同一份原型结构和布局。

本讨论以 `C:/Users/bite/Codetypes/xq-client` 当前工作树为目标运行时依据。2026-11-18 检查时 HEAD 为 `fcd6c1d`，`ui-button.ts` 与对应测试存在未提交修改：当前工作树已经移除 `pressedSkin`，UIButton 只保留 `normalSkin`、`selectedSkin`、`disabledSkin`。GameFlow 的本次模型、编辑器及导出统一采用这三个状态。

当前目标源码中的 `UIRadio` 与 `UICheckBox` 均继承 `UIBox`，通过 `skin` 引用直接子节点，并按 `selected` 控制该子节点显示或隐藏；GameFlow 当前模板也已使用“底框”“选中标记”和独立文字子节点。此结构作为图片配置建议的依据。

目标源码 `src/game/app/core/ui/ui-progress-bar.ts` 的 `UIProgressBar.mode` 提供 `horizontal`（横向）和 `circular`（圆形）两种模式。横向按进度管理填充子节点宽度，圆形保持整图尺寸并由图片绘制按进度显示扇区；圆形填充子节点必须是 UIImage 或 Laya.Image。ProgressBar 的内置图片方案需同时讨论两种模式。

GameFlow 当前 `WidgetProps` 只有横向/纵向 direction，没有 ProgressBar mode；`node-view.tsx` 的 progress 使用简单条形绘制，`ui-parts.ts` 的 skin 控件集合也尚未包含 progress。因此本次需要同时补齐模型、图片部件、属性编辑和画布/预览行为。

## 2. Goals

- 原型、美术 PSD、预制体资源三种模式使用完全相同的原型节点、层级和布局。
- 将控件外观从 CSS/Canvas 风格绘制迁移到明确的图片资源槽位。
- 没有美术 PSD 时，仍能使用内置资源导出可装载的 Prefab 资源。
- PSD 结构能表达运行时控件的图片槽位，并保持 UILabel 等独立节点。
- 最终导出的 UIButton 属性与 xq-client 当前三态皮肤契约一致。
- 原型 ProgressBar 补齐横向和圆形模式，在编辑、预览、保存和导出中保持同一模式及进度语义。

## 3. Non-Goals

- “预制体”模式当前不读取或验证真实 Prefab 节点结构，只使用原型结构装载已导出的资源。
- 不修改 xq-client；直接更新项目自带示例，不新增旧文档自动转换逻辑。
- 不通过自动变暗、着色或 CSS 绘制伪造缺失的状态图片。
- 不把 UIButton 文字合并进按钮状态图片。

## 4. Confirmed Decisions

### 4.1 三种资源模式

- **原型**：所有图片槽位仅使用 GameFlow 内置图片资源；即使已绑定 PSD 或存在已导出的磁盘图片，也不改变此模式的图片来源。
- 打开原型文件时，默认进入“原型”模式。
- 用户主动清空的图片槽位保持为空，不因进入原型模式而自动补图；未配置的 UIButton selected/disabled 状态仍按三态规则回退到 normal。
- **美术 PSD**：使用当前 PSD 生成的内存资源。
- **预制体**：使用原型结构装载已经导出到磁盘的资源；不宣称验证真实 Prefab 结构。
- 没有 PSD 时，Prefab 导出使用内置资源，不因缺少美术文件而阻断结构交付。

### 4.2 UIBox 外观

- UIBox 本身只负责容器、布局、裁剪、变换和层级，不继续直接绘制填充、描边或圆角。
- 新建 UIBox 默认是透明纯容器，不自动创建背景 UIImage。
- Box 需要背景时使用内部 UIImage 子节点；背景随 Box 复制、移动、隐藏、缩放和裁剪。
- UIBox 属性面板的“外观”分区提供“添加背景图片”按钮；每点击一次，新增一个普通 UIImage 子节点，允许重复添加。
- 该操作只负责添加图片，不判断已有背景，不设置专用背景角色或 backgroundNodeId，也不提供背景识别、更换或移除的专用管理。
- 新增图片作为真实子节点显示在图层树中，后续使用普通 UIImage 的选择、资源替换、层级调整和删除操作。
- 内置纯色色块是实际图片资源，不是 Box 的颜色样式字段。

### 4.3 UIButton 结构

- UIButton 继承 UIImage，自身持有图片资源；不为按钮背景额外创建 UIImage 子节点。
- UIButton 没有文本属性。按钮文字使用独立 UILabel 子节点。
- UIButton 原型控件提供三个图片槽位：`normalSkin`、`selectedSkin`、`disabledSkin`。
- 新建 UIButton 只自动设置内置 `normalSkin`；`selectedSkin` 和 `disabledSkin` 默认留空。
- 三个图片槽位都允许清空。`normalSkin` 为空时按钮不绘制图片，但仍保留尺寸、命中和交互能力。
- 空 `normalSkin` 不阻止保存或导出；编辑器提示该按钮当前不可见。
- 状态优先级为 `disabled > selected > normal`。
- `selectedSkin` 或 `disabledSkin` 缺失时，目标运行时回退到 `normalSkin`。
- `pressed` 仅表示按下状态，不对应图片槽位；按压反馈可由目标项目已有缩放效果组件处理。

### 4.4 UIButton 的 PSD 槽位

带 UILabel 的按钮在 PSD 中以控件组表达：

```text
登录按钮                    # UIButton 组
├─ @normal                  # normalSkin
├─ @selected                # selectedSkin
├─ @disabled                # disabledSkin
└─ caption                  # 独立 UILabel
```

- `@normal`、`@selected`、`@disabled` 可以是单个图层或组；组在导出时合成为对应状态图片。
- UILabel 不进入任何按钮状态图片，保持独立节点和动态文字能力。
- `@normal` 默认可见；另外两个状态建议默认隐藏，避免 PSD 合成预览叠加三种图片。
- 普通 UIImage 和 Box 背景 UIImage 仍使用普通图片槽位，不套用 UIButton 三态命名。

### 4.5 内置资源

- 首批标准按钮至少提供绿色、黄色、红色、灰色等图片。
- 新建按钮默认只设置一张 normal 图片；selected 和 disabled 图片由用户按需单独配置。
- 内置标准按钮使用真实九宫格 PNG，保留固定边角并适配不同 UIButton 尺寸。
- 提供一组简单纯色色块，用于 Box 背景、普通 UIImage 和无美术资源的结构原型。
- 色块分为“纯填充”和“带描边”两类，并与标准按钮资源分开管理。
- 纯填充色块直接拉伸，只提供背景颜色。
- 带描边色块使用实际九宫格 PNG，保持固定描边厚度；UIBox 不恢复自身的填充或描边绘制。
- 普通 UIImage 的默认内置占位图使用浅灰色背景和居中的深灰图片图标，不在画面中显示“图片”文字。
- UIImage 的节点名称只出现在图层树和属性面板；选择边框与缩放控制点属于编辑器覆盖层，不进入内置图片或导出产物。
- 内置资源库还提供一组圆形图片和常用 UI 图标，用于头像占位、状态点、圆形底板及常见操作图形。
- 内置资源也需覆盖 Radio（单选）和 Checkbox（复选）两类控件所需的图片，作为真实控件部件资源用于原型显示和导出，并归入资源选择面板的“单选/复选”分类。
- Radio 提供圆环底图和实心圆选中标记；Checkbox 提供方框底图和对勾选中标记。
- 两类控件均保持底图常显，未选中时隐藏选中标记，选中时在底图上显示标记，沿用现有子节点部件结构。
- Radio/Checkbox 的说明文字由独立 UILabel 表达，图片不包含文字；图片沿用前面确定的简洁风格。
- Slider 首版提供轨道底图和圆形滑块图片各一张，沿用现有“轨道＋滑块”的子节点部件结构。
- Slider 轨道底图使用可拉伸的细条图片；滑块使用独立圆形图片，随数值移动。两张图片延续前面确定的简洁风格，作为真实资源参与原型显示和导出。
- 圆形图片分为“纯填充圆形”和“带描边圆形”两类；描边属于图片内容，不由 UIImage 或 UIBox 额外绘制。
- 圆形图片和图标都是可被 UIImage 引用并进入 Prefab 资源导出的真实图片，不复用只存在于编辑器界面的 Lucide 图标。
- 首批图标库约 20 至 30 个，同时覆盖常用操作和游戏语义。
- 已确认的操作图标包括设置、加、减、收藏、返回、搜索和关闭；游戏图标覆盖战斗、属性、货币、背包和奖励等常见原型语义。
- 全部图标采用与默认 UIImage 占位符一致的简洁线框风格，统一线宽、端点、圆角和视觉尺寸，不混用多套图标语言。
- 首版图标 PNG 使用透明背景，只保留线框图形，以便叠加在按钮、圆形底板、色块和其他 UIImage 上；实际视觉验收后再调整或补充变体。
- 内置资源必须能进入正式导出流程；不能只存在为编辑器 CSS 或临时 Canvas 绘制。

### 4.6 美术资源缺失与回退

- 按控件的图片槽位判断。未绑定美术且已配置内置图片的槽位，在美术 PSD 模式中显示内置图片，导出 Prefab 时使用这份内置资源。
- 在美术 PSD 模式中，已绑定美术的槽位如果找不到 PSD 图层或切图失败，在对应控件上显示异常占位，不自动回退内置图片。
- 在预制体模式中，预期的磁盘资源尚未导出、缺失或损坏时，显示异常占位，并提示“尚未导出”或具体读取错误。
- UIButton 未配置的可选状态仍沿用三态规则，显示该模式所用的 `normalSkin`；已经绑定但读取失败的状态显示资源异常。
- 导出 Prefab 前若检测到已绑定资源缺失或失效，主动提示“有资源缺失，是否继续导出？”，列出受影响的控件、图片槽位和资源。
- 提示提供“取消”和“仍然导出”：取消则终止本次导出；用户选择仍然导出后继续，不因资源缺失直接禁止导出。
- 用户主动清空的图片槽位，以及未配置的 UIButton selected/disabled 状态，不作为资源缺失提示。
- 用户选择“仍然导出”后，保留缺失图片槽位原本的资源引用，缺失的图片文件暂不输出；页面结构、布局、UILabel 和其他正常资源照常导出。
- 不将缺失引用清空或自动替换成内置图片；在预制体模式中，该位置继续显示异常占位，便于定位并补齐资源。

### 4.7 内置图片选择入口

- 点击图片槽位时，统一打开内置资源选择面板。
- UIImage 的图片槽位与 UIButton 的 normalSkin、selectedSkin、disabledSkin 共用这一选择入口。
- 面板按“按钮”“色块”“圆形”“图标”“单选/复选”五类展示内置资源，供当前图片槽位选择。
- “单选/复选”分类中，Radio 的圆环底图与实心圆标记放在一起，Checkbox 的方框底图与对勾标记放在一起，方便配套选择。

### 4.8 项目自带示例更新

- 本次重设计直接修改项目自带示例，不新增打开、导入或保存旧文档时的自动转换逻辑。
- 示例中的旧容器背景直接改为普通 UIImage 子节点，旧按钮文字直接改为独立 UILabel 子节点；按钮自身图片改为新资源槽位，不保留额外背景 UIImage 来替代按钮自身皮肤。
- 新资源字段实现时，同步更新 `sample/` 下的相关示例，以及 `examples/` 中对应的示例副本、生成脚本和映射资料，避免重新生成时恢复旧结构。
- 示例保持原有页面内容和布局；本轮不提供运行时自动迁移或另行编写批量转换工具。

### 4.9 原型 ProgressBar 模式补齐

- 本次重设计包含原型 ProgressBar 的模式特性补齐，同时支持与目标 UIProgressBar 对应的 `horizontal`（横向）和 `circular`（圆形）；不只是补充内置图片。
- 属性面板提供“模式：横向 / 圆形”，新建默认横向，保留最小值、最大值和当前值设置；ProgressBar 模式独立于 Slider 等控件的横向/纵向 direction。
- 编辑画布和运行预览均按当前模式及数值显示实际进度；横向按比例显示填充宽度，圆形按比例显示完整图片的扇区。调整模式或数值后即时更新。
- 填充使用独立 UIImage 子节点并对应目标运行时的 skin 引用；圆形模式保持整图尺寸。底图和填充的具体配色、样式仍按待确认资源方案处理。
- 原型、美术 PSD、预制体三种资源显示模式共用 ProgressBar 模式与进度计算，仅切换图片来源。
- 模式、数值和图片部件引用能够保存、重新打开并撤销/重做；PSD 资源映射及 Prefab 导出需保留与目标运行时一致的模式、数值和填充部件关系。

### 4.10 输入框创建

- 原型中新建输入框时，仅创建 UITextInput 节点，不自动生成外层 UIBox 或背景 UIImage。
- 需要背景时，由用户手动添加普通 UIImage，并按实际页面需要组织层级。
- 输入文字、占位文字、密码等输入属性继续由 UITextInput 负责。

### 4.11 ComboBox 图片部件

- ComboBox 继承 UIBox，背景 UIImage 和向下箭头 UIImage 由用户按需手动添加到控件内部，不生成额外外层容器。
- 当前选项通过独立 UILabel 子节点显示，属性面板提供 textLabel 节点引用，选项变化时更新该文字节点。

## 5. Current Recommendations

- UIButton 属性面板用三个图片资源行替换填充、描边、描边宽度和圆角，并提供普通/选中/禁用预览状态切换。
- 用户只配置 `normalSkin` 时保持另外两个槽位为空，依赖目标运行时回退；工具不自动生成变暗或灰度图片。
- 选择标准颜色按钮图片时只替换 `normalSkin`，不隐式修改用户已有的 selected 或 disabled 配置。
- 首批图标建议控制在约 20 至 30 个，并按“常用操作”和“游戏语义”分组选择。
- ProgressBar 建议分别准备横向和圆形两套图片：横向使用浅灰底槽与绿色填充，圆形使用浅灰底环与绿色进度环；底图常显，填充子节点由进度控制。图片不包含百分比文字，需要文字时使用独立 UILabel。首版采用上述灰底绿进度方案，后续可按界面验收调整图片。

## 6. Implementation Decisions

- 2026-11-18 用户授权开始实现，常规技术细节由开发决定；需要产品决定的剩余问题于 2026-11-19 汇报。
- 新增可序列化图片槽位 ImageSlot，分别记录内置图片 ID 与可选美术切图引用。UIButton 三态独立持有槽位；原型显示始终只解析槽位内置来源。
- 槽位中只有美术绑定而没有内置 ID 时，原型来源视为空；UIButton 可选状态未配置内置图时，原型模式沿用 normal 的内置图，不加载其美术图片。
- 显示模式是会话状态，默认原型；不会改变导出采用的美术优先、无绑定使用内置资源的规则。
- 内置资源以实际 PNG 与清单落盘；按钮与描边色块携带九宫格。图标提供 28 个统一线框 PNG，内置尺寸与边距由清单管理。
- 三个资源显示按钮放在原型底部工具栏。资源选择保留已确认五类；滑块与进度条资源放在按钮分类中的控件部件区域。
- PSD 控件保留槽位与稳定节点元数据共同建立映射，UILabel 保留用户名称。具体颜色和资源细节可在实际效果验收后调整。
- “添加背景图片”入口适用于自由布局容器，每次新增普通 UIImage；横排、竖排、网格和列表不提供该快捷入口，以免背景成为参与排列的内容。示例中的布局背景直接使用普通兄弟图片。
- 当前页提供“生成 PSD / 关联 PSD 图片 / 导出 Prefab”。生成 PSD 使用内置图片，按钮状态以 `@normal` / `@selected` / `@disabled` 层表达；文字保留独立可编辑层和栅格缓存。关联动作显式执行，不按图层名字猜节点。
- Prefab 输出包含 `.lh`、PNG、`.png.meta` 与根目录来源清单，成功资源用 importer UUID 引用，已有合法 UUID 继续复用。写入前统一检查两类根目录、来源冲突和未保存目标；写入失败尝试恢复本次文件。
- 本次不新增控件组合预设、旧文档资源自动转换或目标工程源码修改。

## 7. Implementation Plan

1. 模型、内置 PNG 资源和统一选择面板，UIButton 三态与普通 UIImage 槽位。
2. UIBox 背景按钮，Radio/Checkbox/Slider/ProgressBar 图片部件及 ComboBox textLabel 引用，原型编辑与运行预览一致。
3. 三种资源模式及资源缺失诊断；PSD 生成与 Prefab 导出保持图片槽位关系，允许缺失资源确认后继续。
4. 直接更新自带示例与生成资料；执行模型、资源隔离、部件状态、导出、保存恢复测试及界面验收。

## 8. Testing Plan

- 模型测试覆盖三个皮肤槽位、UILabel 独立性和序列化。
