# 切图装载运行预览

Status: Done
Date: 2026-11-17
Scope: 复用工作台已有控件与布局，装载真实内存切图及已有导出资源，提供页面运行预览与九宫格检查。

2026-11-23 后续：[画布预览与 Prefab 动作归位](canvas-prefab-action.md) 移除了独立运行预览弹窗及临时控件会话。本文保留首轮资源生成、九宫格和共享绘制的历史决策；当前预览表面为原型画布的三种资源模式。

后续九宫格中段缩减和最终参数已单列为[九宫格切图产物与导出参数](nine-grid-export-product.md)；本文保留首轮验收范围。

## 1. Context

用户明确：运行预览基于工作台已实现的 UI，主要查看切图后的装载情况；与项目 Laya UI 行为不同的实现，应作为工作台的 BUG 核对和修复。运行预览不以启动 Laya 引擎或完整游戏为前提。

用户进一步明确职责：美术交付 PSD，最多指定哪些图层/组需要切、如何切及九宫格等规则；全部切图由 GameFlow 工具执行。工具负责生成图片、资源描述及装载结果，不能要求美术手工导出 PNG 作为流程前提。

用户明确切图产物可以完全保存在内存中：虚拟切图生成的图片/纹理与配置已经是真实数据，是否保存本地属于独立的导出步骤。运行预览直接装载内存产物，不要求先写文件或先编码 PNG 再解码。

## 2. Goals

- 同一页面在编辑和运行预览中使用同一套布局、变换、裁剪及控件实现。
- 将实际切图及其九宫格、尺寸信息装载到页面控件，检查资源与布局的组合结果。
- 以 PSD 和切图规则为输入，由工具完成合成、裁切、资源生成和装载；预览与后续交付消费同一批生成资源。
- 以项目实际 Laya UI 源码和已确认契约为对齐依据；发现差异时定位根因，在共享实现中修复并补回归。

## 3. Non-Goals

- 首轮不嵌入完整 Laya 运行时、游戏业务、服务器连接或 Prefab 导出管线。
- 不另建一套只供运行预览使用的布局和控件规则。
- PSD 已保存合成图用于对照，不能替代切图装载结果。

## 4. Current Behavior and Evidence

- `shared/ui-layout.ts` 已实现约束、容器排布、变换、裁剪及 Slider 部件位置；`webview/editor/node-view.tsx` 消费解算结果绘制节点。
- `shared/psd-meta.ts` 保存切图启用状态、稳定身份、名称及九宫格；`webview/psd/psd-worker.ts` 读取支持的单层 PNG。
- `webview/psd/slice-render.ts` 生成并缓存裁切/透明填充后的 Canvas；页面和独立九宫格检查共用 `runtime/paint-slice.ts`，正式 PNG 导出编码同一批生成像素。
- 图片节点通过可保存的 `sliceResource` 关联资源，属性面板显式选择来源切图；旧 `imageData` 继续支持未绑定图片，绑定异常不回退旧图片。星海远征显式映射仍仅是验收材料，不自动猜测绑定。
- 核对 xq-client `ui-image.ts` 与 `engine/libs/laya.core.js` 的 `writeNineGridAxes`：普通图片缺省按控件尺寸铺设，九宫格支持重复，小目标优先保留前侧边界且不扩大控件。显式 contain/cover 继续作为工作台选项，不宣称目标 UIImage 具有相同属性。
- 生成资源自然尺寸进入共享布局及反向编辑。修复了绘制使用自然尺寸、编辑却使用旧 frame，导致移动被误判为缩放并冻结 measured 模式的问题；回归覆盖移动、单轴缩放、锚点/约束、重挂接、复制和组件提取。
- 中文显示名与 ASCII 导出名遵循已实现的 `psd-export-names`，路径作用域遵循 `file-export-directory`。文本使用已接入的目标排版适配，不把完整引擎/字体像素一致性列为本轮完成结论。

## 5. Proposed Behavior

工作台提供“运行预览”，默认按原型控件和布局组装切图。页面的结构、文字、控件引用保持来自原型；图片内容与九宫格来自所绑定的切图资源。PSD 原图可并排或叠加对照。

建议流程为：

1. 美术制作和更新 PSD；可指定要切出的图层/组、区域、九宫格和填充方式。切图规则可在工作台配置并沿用已有元数据保存机制，不预设 Photoshop 已有专用标记界面。
2. 工具读取 PSD 和规则，对指定的导出对象执行合成、裁切，生成图片以及尺寸、透明边界和九宫格资源描述。动态文字是否进入图片由明确导出范围决定。
3. 工作台维护“原型节点/资源槽位 → PSD 导出对象 → 生成资源”的关联。有已验证映射时复用；外部 PSD 无映射时首次指定，不能按同名猜测。
4. 运行预览装载本次生成的资源，使用原型布局呈现整页；不要求用户重新手工选择每一份生成 PNG。
5. PSD 或切图规则变化后，工具重新生成受影响资源并更新预览。同一导出对象保持资源身份，原型结构与布局的修改继续通过独立文档事务完成。

预览重点检查：图片是否加载、绑定是否正确、位置和尺寸、透明边界、九宫格拉伸/重复、层级与裁剪，以及已支持控件状态下的部件显示。缺图、无效绑定和不支持的切图明确定位到控件。

预览中的状态调整和重置只作用于临时会话，不覆盖设计初值。需要调整设计布局或正式资源绑定时，回到既有文档事务中编辑。

### 5.1 九宫格必须验证切图后的重建结果

用户指出：装配时使用切图前的图片，会掩盖实际九宫格切图问题。因此“切图产物预览”经过同一处理路径：PSD + 规则 → 内存切图处理 → 内存中的图片/纹理 + 产物配置 → 控件装载 → 九宫格重建。产物无需落盘，编码与重新解码也不是预览前提。关键是消费切图处理结果并执行正确重建，不能在包含裁切、合成或缩减等步骤时绕过它们直接展示切前原图。

九宫格提供三个检查视图：

1. **实际产物**：查看工具生成的纹理、产物像素尺寸、九宫格边界、填充方式和对应来源。若切图包含透明裁切或中段缩减，展示处理后的图片及与其对应的配置，不使用切前坐标描述切后纹理。标记九宫格本身不代表必须将中间缩成一像素；可缩减区域与重复纹理保留规则须在实际切图契约中定义。
2. **原尺寸还原**：用产物重建到原型中该控件的设计尺寸，检查缺边、错位、透明边界和接缝；可与对齐的 PSD 源对象叠加或比较差异。整页仍包含独立文字与布局，不以整页像素完全等于 PSD 作为唯一正确性标准。
3. **变尺寸检查**：在临时预览中分别改变宽、高及两者，并覆盖小尺寸。即使切图产物正确装载，原尺寸下错误的九宫格分界也可能刚好拼回原图，必须检查拉伸后的角部、边线、中心和重复纹理。预设示例：490×94 的按钮分别查看设计尺寸、700×94、490×150、700×150；不把放大原图作为拉伸后正确结果的参考。

临时目标尺寸交给公共布局与九宫格渲染计算，画布缩放仅改变观察比例；两者不能混用。预览中可显示资源已生成/正在生成/生成失败状态，来源或规则改变后不能把旧产物标成新版本成功。

### 5.2 中文图层名与统一目录资源名

用户确定采用名称识别导出资源，替代此前按 assetId 自动命名的建议：图片输出到资源根目录加文件 `exportDirectory`；相同相对路径代表同一资源，不同子目录同名互不冲突。各实际导出目录中的 `gameflow-resources.json` 记录来源 PSD、文档/图层身份、源版本、图片 hash、尺寸和九宫格。PSD ID 用于来源追踪，不能绕过名称冲突。

- 保留中文图层名。自定义 `exportName` 留空时，通过 placeholder 显示默认名，不把默认值写入输入框。
- 图层名包含“按钮”时非共享默认 `btn_{PSD文件名拼音首字母}_{图层名拼音首字母}`，共享默认 `btn_{图层名拼音首字母}`，其他图层前缀为 `img_`；去掉 PSD 扩展名，已有 ASCII 英文数字保留并小写。自定义名优先且不自动添加前缀，也不随共享切换变化，清空恢复默认。
- 同一 PSD 内同名图层代表同一资源，两个同时标记导出时报冲突，即使自定义名不同；不同图层的有效导出名碰撞也报冲突，不追加随机 ID 或编号。
- 目录同名文件由当前 PSD 生成时允许更新；其他 PSD 生成或无法确认来源时，未勾选共享则报冲突。用户明确“共享且导出就覆盖”：勾选共享允许覆盖并将来源记录更新为当前 PSD，不解释为只读复用。未勾选导出的层不写文件。
- 图层树名称右侧显示冲突标记，父分组也显示后代冲突；悬停或选中查看原因。目录冲突在实际导出预检后回传到相应图层，写文件前检查整个批次。
- 未自定义时，图层改名或切换共享会改变默认输出名；PSD 改名仅影响非共享默认名。工具不自动删除旧输出。需要固定文件名时填写自定义名称。原型程序变量名与资源名独立。

具体实现、保存边界和验证见 [PSD 资源命名与目录导出](psd-export-names.md)。整页运行预览的后续绑定应按统一目录资源名解析到内存资源及来源，不再以独立 assetId 决定文件名。

## 6. Design

### 6.1 本轮实施契约（2026-11-17）

用户要求先实现。以下为本轮可运行的默认行为，跨文件自动改名/搬迁继续讨论，不阻塞装载链路：

- 图片节点新增可选 `sliceResource`，保存资源相对根目录的 PNG 路径及可选 PSD 文档/图层来源提示。通过现有文档事务保存、撤销和组件实例覆盖；不写本机绝对根目录、不保存生成像素。未绑定的既有内嵌图片继续使用；已绑定资源失败不能回退内嵌图。
- 属性面板明确选择已打开 PSD 的已标记切图，或填写已有导出资源路径。按钮/Slider/CheckBox/Radio 通过现有图片子节点绑定，不新增平行皮肤槽位。初次不按同名猜测绑定。
- 资源键为 `exportDirectory/有效导出名.png`，目录省略时为根目录文件。内存产物不要求设置导出根目录；本会话保留已读 PSD 的生成结果。相同路径跨 PSD 仍执行非共享冲突/共享覆盖规则。
- 优先装载本次 PSD 生成的 Canvas 与描述；未在内存生成的路径可读取根目录内已有 PNG 和同目录来源清单，验证 hash、尺寸及九宫格。生成中、失败、改名、取消导出或来源删除均明确诊断，禁止取同路径旧磁盘图掩盖当前失败。
- PSD 元数据变化后立即使旧产物失效，异步生成结果按版本提交，旧请求不能覆盖新配置。导出将同一缓存 Canvas 编码为 PNG；预览不编码/解码生成图片。
- 顶部纯图标“运行预览”在当前工作台内打开页面预览，复用 NodeView 与 resolvePageLayout。预览会话包含控件状态、单控件尺寸、重置，以及实际产物/设计尺寸/变尺寸检查；全部不进入文档历史。PSD 原图另列为对照。
- 普通图片默认按控件尺寸铺设，保留显式 imageFit；资源自然尺寸进入公共布局的 measured 尺寸。九宫格渲染由页面和独立切图检查共用，覆盖 repeat 及小于两边之和的目标尺寸，以实际目标源码核对。
- 自然尺寸也传入反向编辑、约束/锚点转换、重挂接和复制几何。否则绘制使用资源尺寸、编辑仍使用旧 frame，会把一次移动误判成缩放并丢失 measured 模式；回归验证移动不冻结资源自然尺寸。
- 沿用当前可独立导出的单层、区域及九宫格能力；复杂效果/组导出明确报不支持。本轮不实现九宫格中段压缩或游戏/Prefab 运行时。

“统一目录”均按上述相对路径作用域理解；中文显示名及 ASCII 导出名由 psd-export-names 实现，区域 Canvas 及 PNG 输出由 psd-slice-region 实现。

```text
美术 PSD + 切图规则 ─ 内存切图处理 ─ 图片/纹理与资源描述
                                         ├─ 控件绑定 + 共享渲染 ─ 运行预览
                                         └─ 按需编码并保存 ─ 本地资源
```

- 预览与编辑复用 `resolvePageLayout` 和节点渲染；内存资源的尺寸及九宫格通过公共资源接口进入布局与渲染。
- 原型控件用有作用域的稳定节点 ID 定位，复用组件区分源节点和实例；绑定的图片资源按统一目录内的有效资源名解析，清单记录 PSD 来源身份。初次控件到资源的关联仍须明确指定。
- 切图生成与预览装载采用同一资源描述，保留尺寸、九宫格及透明填充像素；持久绑定位置为 §6.1 的节点字段，产物像素不进入原型文件。
- 生成资源是 PSD 与切图规则的派生产物。资源名用于识别目录中的同一资源，来源身份用于追踪生成 PSD，PSD 内容和规则版本用于判断是否需要重新生成。预览装载生成图片，PSD 合成图仅作对照。
- 产物装载接口消费生成后的内存图片/纹理与配套资源描述，直接进入共享渲染；预览与正式导出使用同一份生成结果。实际存储可采用 ImageData、ImageBitmap、Canvas 或适合渲染器的纹理表示，不要求为预览额外执行文件 I/O 或编码/解码。正式导出负责将这份结果编码并保存，不另跑一套不同的切图逻辑。产物配置描述处理后纹理，设计尺寸保留在原型中，两者分开。
- 缺失、损坏或生成失败的资源显示对应诊断，不回退到 PSD 原图或原型内嵌旧图片来伪装装载成功。PSD 原图对照使用独立入口，与产物画面明确区分。
- Laya 是行为参考。对于已经承诺支持的布局、控件和资源语义，差异按 BUG 处理；先用具体输入和参考契约确认根因，再修改公共实现，避免只在预览中补偿。
- 可用目标源码、确定性案例和参考结果验证；目标引擎可辅助生成对照材料，不成为日常预览的运行依赖。尚未验证的行为明确列出，不使用“原型近似”作为已支持行为不一致的长期解释。

## 7. Implementation Plan

1. 建立最小资源描述及节点绑定，按统一目录资源名识别图片并记录 PSD 来源，明确保存、重开、改名与实例作用域；退出条件为一个页面能够准确找到各图片资源，命名变化与冲突可定位。
2. 实现工具根据 PSD 标记生成资源，打通现有图片渲染，接入九宫格及自然尺寸；针对发现的行为差异先建立最小复现，再修公共实现。
3. 加入运行预览入口、加载诊断与临时状态重置；提供实际产物、原尺寸还原及多尺寸九宫格检查。退出条件为切图实际装载、独立文字与控件部件按原型组装。
4. 用星海远征登录页及含 Slider/CheckBox/Radio 的设置页验收；记录支持范围和仍待核对的差异。

## 8. Testing Plan

- 绑定：同名不同 ID、图层改名、资源替换、删除、重复身份及组件实例，验证不发生错绑。
- 命名：默认名随源名称派生，自定义名固定；同名图层双选和输出名撞名冲突，跨 PSD 非共享拒绝/共享覆盖。重复生成、清理缓存后重开沿用持久配置和来源清单。控件变量改名不能重命名图片资源。
- 图片：不同宽高比、显式尺寸与自然尺寸、透明边界、九宫格拉伸/重复及小目标尺寸；用确定性资源检查实际装载结果。
- 布局：同一输入在编辑与运行预览中取得相同几何；对已确认 Laya 差异增加具体数值或像素回归。
- 控件：已支持的 Slider 方向/端点/部件尺寸、CheckBox/Radio 显隐与分组状态；临时状态不进入保存和撤销历史。
- 端到端：仅提供 PSD 和切图规则，由工具生成资源后重新装载；检查九宫格、缺图提示及整页结果。更新 PSD/规则后重新生成，身份和绑定保持，未标记内容不意外输出；不能以手工 PNG、PSD 合成图或资源列表替代验证。
- 产物路径：使用具有独特角部、边线和中心图案的确定性图片执行内存切图、装载及重建，全程无需写本地文件；更改生成产物像素必须改变预览，移除/破坏资源必须报错，以证明没有绕回源图。
- 导出一致性：接入正式导出时，将同一内存产物编码后重新解码，独立验证图片及配置与预览所用资源一致。编码/解码往返属于导出验收，不作为每次预览的必经步骤。
- 九宫格分界：构造原尺寸仍能拼回、扩大后会拉坏边角的错误标记，验证多尺寸检查可以暴露差异。覆盖单轴/双轴伸缩、repeat 周期、裁切后边界换算及源尺寸与目标尺寸不同的情况；正确结果来自契约和独立期望值，不复用被测切图函数产生期望。

## 9. Acceptance Criteria

- 无需启动 Laya 或游戏即可查看切图装载后的页面。
- 显示的图片来自所绑定的切图资源，九宫格进入真实页面渲染。
- 九宫格预览直接消费切后的内存图片/纹理和配套配置，无需落盘或先编码再解码；既检查原尺寸还原，也检查控件尺寸变化，不能用画布缩放或切前原图展示替代。
- 修改/破坏生成产物能够在预览中观察到变化/错误，证明装配过程没有使用切前图片代替产物。
- 美术无需手工切图或交付 PNG；PSD 与切图规则足以由工具生成并装载资源。
- 策划/美术可使用中文图层名，工具按约定生成默认 ASCII 名；自定义名优先。同名冲突按共享规则处理并在图层树中可见，覆盖后来源可追踪。
- 编辑和运行预览共享布局与控件规则；已确认的差异由公共实现修复并有回归证据。
- 资源异常可定位，预览状态可以重置，源文档不因预览交互而改变。
- 具体自动化与交互证据、未覆盖范围见下方验证记录。

## 10. Risks and Rollback

PSD 基础像素不一定包含复杂效果，沿用现有切图支持范围并明确报告。资源自然尺寸可能影响内容布局，回归同时覆盖固定和内容尺寸。解除切图绑定可恢复使用既有内嵌图片；运行预览的临时会话可随时关闭/重置，不需要回滚设计文档。
