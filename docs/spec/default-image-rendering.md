# 默认图片背景与图标分离渲染

Status: Done
Date: 2026-11-19
Scope: 内置 image/default 的画布、运行预览、PSD 与 Prefab 输出

## 1. Context / Current Behavior

默认图片为含背景和图标的 64×64 PNG。SlotImage 装载后 ResourceCanvas 调用 paintSlice；fill 把整张图缩放到目标宽高，图标随背景变形并模糊。生成 PSD 同样调用 paintSlice，Prefab 直接写入原始 PNG，因此单改 CSS 或 imageFit 不能解决共同的源头。

## 2. Goals

- 默认图片按浅灰白背景和居中图标分别绘制，背景覆盖全部控件。
- 图标等比绘制，最大宽度 32 个设计像素，宽高均不超过控件的一半；小尺寸缩小，大尺寸不放大。
- 原型编辑、运行预览、生成 PSD 和无美术绑定的 Prefab 输出保持一致。
- 美术图片、普通内置图片和用户图片填充设置保持原有语义。

## 3. Non-Goals

不增加文档字段、控件子节点或自动转换；不改变用户美术图片的拉伸、适应、覆盖和九宫格算法。不增加 Laya 运行时渲染协议；导出的占位 PNG 对应本次布局解算尺寸，改变布局后重新导出。

## 4. Proposed Behavior / Design

1. 仅在图片槽位实际请求 image/default 内置资源时，使用统一 Canvas 绘制器；灰白背景 #e3e7ec 和简洁图片图标 #657385 直接按目标尺寸绘制，不拉伸旧位图。
2. 绘制器保留既有画布像素预算，图标按设计坐标保持比例；fill/contain/cover 对此占位图均使用同一背景加图标规则。
3. PSD 图层及合成图复用相同绘制器，图层身份和绑定元数据保持原有结构。
4. Prefab 先解析实际待导出的美术资源和普通内置资源，用这些资源的自然尺寸解算布局，再由既有浏览器导出解析器生成默认图尺寸 PNG；不从当前预览模式取几何尺寸。仅默认图片使用带尺寸的内置资源路径，不同尺寸可共存；其他内置资源仍直接复用原 PNG。预制体预览按相同布局尺寸读取实际导出 PNG，未导出/缺失时仍报告资源错误。
5. 水平 ProgressBar 的图片按未裁切完整宽度生成，占比仍由进度裁切处理。
6. 资源 hook 保存设计页面中默认图对应的来源尺寸，运行预览临时改宽高继续读取该导出来源。预制体模式仅用磁盘资源尺寸解算占位图路径；磁盘尺寸就绪后可补读对应 PNG，不借用未导出的 PSD 内存尺寸。

## 5. Implementation

- 增加默认图尺寸/路径及完整图尺寸的共享辅助函数。
- Canvas、PSD、Prefab 使用统一绘制入口，保持资源模式隔离。
- 更新预制体资源收集和槽位解析，载入尺寸对应 PNG。

## 6. Testing / Acceptance

- 浏览器像素回归先在旧逻辑下失败：750×1334、横向、正方形和小图，背景角落铺满，图标居中、比例固定且大尺寸不增大。
- 通过真实 SlotImage/NodeView 验证原型模式及不同填充方式；真实美术资源继续依照原填充方式。
- 生成 PSD 并读取图层与合成像素，和原型绘制一致。
- 导出包含不同尺寸默认图的 Prefab，验证 PNG 尺寸、资源路径、来源清单及回读预制体预览像素。
- 共享测试、TypeScript/生产构建、现有相关浏览器验收。

## 7. Risks

目标控件在 Laya 中再次改变尺寸时，导出 PNG 仍遵循 UIImage 的既有缩放行为。本次规则保证原型布局及其 PSD/Prefab 导出快照一致，不向目标引擎注入新的控件代码。

## 8. Verification

- 修复前浏览器直接复现 750×1334 默认图整图拉伸；修复后六种尺寸（含狭长小图）图标居中、比例固定，大尺寸图标 32×28 像素，背景角落不透明。
- 使用软件渲染后端固定 Canvas 抗锯齿，真实 PSD 图层、合成图、Prefab PNG 与原型逐像素一致。
- 真实资源 hook 经来源清单及 hash 校验读取尺寸对应的磁盘 PNG，缺失时明确报错；临时预览缩放保持导出来源；PSD 内存不可用时磁盘图片尺寸可驱动内容测量布局和默认图资源装载。
- 364 项共享测试通过；生产构建通过（仅既有大包提示）；默认图专项、页面 PSD/选择切换、现有三模式整体浏览器验收通过。
- 未新增目标 Laya 动态绘制协议：本次 Prefab PNG 是设计布局快照，目标引擎再次缩放仍遵循 UIImage 行为。
