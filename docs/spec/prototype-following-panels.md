# Prototype Following Panels

Status: Done
Date: 2026-11-13
Scope: 原型图层树与属性面板随页面边界定位

Follow-up: [prototype-panel-top-alignment.md](prototype-panel-top-alignment.md) 将原型两侧统一为 280px，并改为内容顶部优先、400px 可用高度阈值；下方记录为首次实现时的宽度与验收结果。

## Context and Goals

用户希望原型的两个面板与 PSD 切图一样，自动靠近内容边界。当前图层树固定左上，属性面板固定右上并带手动偏移。改为以页面的屏幕矩形为锚点，缩放和平移实时跟随。

## Behavior and Design

- 页面编辑时图层树贴左边，属性面板贴右边，默认间隔 16px、顶部对齐页面。总览只显示选中页面的属性面板，跟随该页面（包括页面拖动预览）。锚点是整页，不随单个控件选择跳动。
- 正常宽度保留图层树 216px、属性 264px，控件不随画布缩放。窄窗口按比例缩窄；两个面板保持左右顺序且不重叠。
- 与切图共用屏幕边界钳制算法，保留边缘空隙，以底部工具条/缩放条实际顶边限定可用高度（窄窗口缩放条会上移）；面板过高时内部滚动。实际高度、视口尺寸、面板收起/展开均通过 ResizeObserver 更新。
- 自动定位替代属性标题的手动拖动偏移；标题保留收起/关闭。面板内滚动/操作不触发画布手势。
- 模式隐藏导致的 0 尺寸观测忽略；返回原型继续使用原相机，重新测量并定位。布局只是视图状态，不修改原型文档、ID、撤销栈或 PSD 配置。
- 初次进入/适应页面预留面板空间。既有 PSD 宽度、相机和定位结果保持一致。

## Implementation and Verification

1. 抽取切图现有定位算法为共享屏幕面板工具，保持原 PSD 接口。
2. 原型观察视口及两面板高度，传递计算后的定位样式给层级树和属性面板。
3. 验证正常贴边、平移缩放、极端越界、不同面板高度、窄窗口、只显示单面板；构建和现有 PSD 回归通过。
4. 浏览器验证进入页面、平移/缩放、属性收起、面板内部滚动、模式切换和总览页面拖动。

## Risks and Rollback

窗口太窄或页面放得太大时允许面板覆盖部分页面，以保证面板可操作。适应画布可重新留出空间。本轮不改变文档数据格式；回退仅涉及视图定位。

## Verification Record

- 构建及 66 项测试通过，其中新增两项原型面板测试覆盖不同宽度、移动/缩放、收起高度、单面板和极端越界；既有 PSD 面板回归通过。
- 浏览器正常窗口页面 x=450.55、宽=330.91，图层树右边=434.53，属性左边=797.45，两侧间距约 16px。拖动画布 +100/+20 后，页面及两个面板分别同步移动相同距离。
- 放大至 300% 时面板宽度不变并停在屏幕内。属性区滚动不改变相机；收起后重新贴齐页面顶部；PSD 模式往返保留相机。
- 720×480 窗口发现缩放条被 CSS 上移、固定 footer 无法避让。改为观测两条工具栏实际顶边后，面板底部 364px，缩放条顶部 376px；360×320 下两面板缩窄、内部滚动且互不重叠。已恢复默认窗口尺寸。
- 总览拖动选中页面后属性面板贴住新右边缘，层级树保持隐藏；撤销恢复页面。截图保存，浏览器无 console error。
- 未重复运行真实 Extension Host；本轮只变更 Webview 面板视图。
