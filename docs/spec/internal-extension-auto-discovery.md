# Automatic Internal Extension Discovery

Status: Superseded
Date: 2026-11-26
Scope: 统一更新器自动发现当前本地 Profile 已安装的内部插件，无需手动加入更新检查；GameFlow 显示名改为“原型工作台”。

当前流程已由 [embedded-extension-updates.md](embedded-extension-updates.md) 取代：只安装业务插件，由插件自己读取对应 metadata.json。以下保留独立更新器方案的历史实现和发布记录。

## 1. Context and Goals

变更前更新器 0.1.2 只检查 state.managed 中的插件，默认仅包含自身。用户手动安装 GameFlow 0.1.0 后仍需再选择“加入更新检查”，不符合安装后自动检查新版的预期。

更新器应自动识别签名目录里、本机当前 Profile 已安装的内部插件，并自动提示新版；用户仍点击“安装更新”后才下载安装。统一更新器仍只需首次安装一次，业务插件不嵌入重复更新客户端。

## 2. Behavior and Boundaries

- 每次目录验签后，在原子状态事务中发现已安装的目录插件；使用当前 Profile 的 VS Code 扩展注册表和安装路径判断，自动补入检查集合，保留已有 pin/pending/目录序号。
- 不自动安装未安装的目录条目，不发现隐藏的验收探针；已经显式纳入的隐藏探针保留原行为。远端、开发环境及其他安装目录继续排除。
- 启动约 30 秒后、之后每 6 小时检查；当前 Profile 的扩展列表变化时也自动检查，覆盖更新器启动后才手动安装的 GameFlow。
- 每个插件提供“暂停更新检查 / 恢复更新检查”，暂停记录在 Profile 的 excluded 状态，后续发现不能重新加入。全局 off 保持暂停，手动检查仍可用。
- 旧状态缺少 excluded 时按空集合迁移。旧版本未加入的已安装内部插件会自动发现；旧 pin、pending 以及全局 off 保留。
- 发布更新器 0.1.3，不覆盖 0.1.2。所有升级包含更新器自身，继续提示确认。
- 按用户追加要求将业务插件显示名、配置标题、命令分类、编辑器入口、README 和 Webview 标题改为“原型工作台”。保持扩展 ID、命令 ID、配置键、协议及文件格式不变，作为同 ID 的 0.1.2 发布；以固定业务源码 `55b3099` 加命名/版本变更构建，不混入当前其他工作项。

## 3. Implementation and Validation

1. 同步基线、首次发布测试步骤及安装文档，去掉必需的“加入”操作。
2. 覆盖未 enroll 的全新/旧状态自动发现、启动与扩展安装事件、暂停的持久化与恢复、固定版本、Profile 和安装目录边界、隐藏/未安装条目排除。
3. 执行分发测试并构建 0.1.3，发布后按域名验证目录签名、版本、下载大小与 SHA-256。

## 4. Acceptance

- 安装更新器 0.1.3 与 GameFlow 0.1.0 后，不运行 enroll 命令，自动检查能提示“原型工作台 0.1.0 → 0.1.2”；确认升级后扩展详情显示“原型工作台”，扩展 ID 仍是 `codetypes.vscode-gameflow`。
- 用户关闭提示或选择“稍后”时无 VSIX 下载；确认后才执行安装，pending 防止重复。
- 暂停后的插件不会在下一次检查或重启时被自动加入，恢复后可再次提示。
- 新目录条目只要未安装就不会被安装或提示，Profile/远端/开发/隐藏边界仍成立。
