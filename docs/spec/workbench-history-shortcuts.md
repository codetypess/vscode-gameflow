# 工作台撤销与重做快捷键

Status: Done
Date: 2026-11-26

## 问题与根因

原型画布按一次 Ctrl+Z，VS Code 会提示已有撤销或重做正在运行。原型和 PSD 切图都在 window 的 keydown 监听器内调用 preventDefault，并经各自的文档会话请求宿主执行原生命令。VS Code 1.148 的 Webview 同时在 window 监听冒泡事件，其 handleInnerKeydown 会将按键转发给工作台，已取消默认行为的事件也会被转发。同一次按键因此能进入同一份文档的原生历史两次。

## 行为与实现

画布在 document 冒泡阶段接管 Ctrl/Cmd+Z、Ctrl/Cmd+Shift+Z 和 Ctrl/Cmd+Y，阻止已接管的按键继续冒泡，再通过现有会话执行一次撤销或重做。输入控件、菜单和弹窗沿用各自的焦点处理。工具栏和 VS Code 菜单继续使用已有的原生历史。修复范围限于快捷键分发。

## 验收

- 监听 Webview 的 window 并记录历史命令。原型与已打开的 PSD 切图各按一次历史快捷键时，只收到一个会话请求。连续按键受已有会话的同步顺序约束。
- 在原型中连续修改两个属性，按一次撤销仅恢复第二项，重做后恢复两项。检查输入框焦点和工具栏按钮。
- 运行共享回归、生产构建和 VS Code 原生历史集成测试。

## 验证结果

修复前的 Chrome 回归记录到两个原型按键和两个 PSD 按键全部到达 window。修复后四个按键均由画布接管，原型重做等到撤销完成才发送，PSD 正在处理命令时也不会再次转发按键。浏览器预览中连续修改两个控件属性后，单次撤销恢复第二项，重做恢复该项，在图层搜索框内撤销保留文档状态。403 项共享测试、55 项 VS Code 原生集成检查及生产构建通过。
