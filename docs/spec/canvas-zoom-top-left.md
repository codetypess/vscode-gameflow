# 画布缩放条移至左上角

Status: Done
Date: 2026-11-16
Scope: 原型画布缩放条及相邻浮动控件的布局。

## 目标与设计

用户要求把右下角的缩小、比例、放大和适应画布控件移至左上角，并与页内层级导航放在同一行。左侧为缩放条，右侧为导航，两者垂直居中；窄窗口保持单行，导航在剩余空间内横向滚动，并缩小左侧边距。

两组控件共用 3px 内边距，外框均高 34px，上下边缘对齐。原来缩放条使用 2px 内边距、导航使用 3px；内部按钮均高 26px、边框均为 1px，因此外框分别为 32px 和 34px。之前仅垂直居中掩盖不了高度差。本次在 CSS 排布边界统一内边距，普通/窄窗口及长导航回归均需比较外框 top、bottom 和 height。

长导航溢出时，原生水平滚动条还会额外占 10px，浏览器复现中将导航外框从 34px 增高至 44px。因此共享外框高度固定为 34px；导航保留横向滚动并隐藏原生滚动条，避免挤压 26px 按钮，键盘和自动定位仍可滚动到路径末端。

浮动图层树和属性面板的顶部预留缩放条及层级导航空间。底部可用高度只由底部工具条限定，避免左上缩放条被当作底部边界而将面板高度压缩为零。沿用现有缩放、适应、平移与历史逻辑；PSD 工作区不在本次范围。

## 实施与验收

1. 将缩放条与层级导航放进同一浮动 flex 行，缩放条不收缩，导航可收缩并横向滚动。
2. 更新浮动面板顶部预留与底部控件测量，保留面板跟随及内部滚动。
3. 浏览器检查总览、页内与窄窗口：缩放条在左上、导航与面板不遮挡；放大、缩小、适应画布可用，平移后控件位置固定。
4. 运行类型检查、生产构建、现有测试和差异空白检查。此布局调整采用真实浏览器验收，不增加镜像 CSS 的静态测试。

高度差的回归使用浏览器实测边框盒；仓库尚无 DOM 组件自动化测试入口，纯模型测试不能覆盖 CSS 盒模型差异。手动步骤：打开样例、进入页面，分别在普通/窄窗口及容器层检查两组外框均高 34px，且 top/bottom 相同，再操作缩放与导航。

## 验证记录

- 同一行调整后 `npm run build` 通过，包含两份 TypeScript 配置检查及生产打包；首轮 `npm test` 的 177 项现有测试通过。
- 本地星海远征样例实测总览与页内：浮动行位于画布左上 16/12px；缩放与导航中心 Y 均为 69px，两者间隔 8px；页内面板顶部从 140px 收回至 100px。放大 39% → 47%、缩小与适应回 39%，导航进入/返回容器正常。
- 首轮已验证 720×480、360×320 的面板避让及平移。同行布局复验 360×320：浮动行位于画布左上 8/8px，缩放与导航保持单行、中心 Y 均为 65px，两面板等宽收缩至 160px，顶部保持 100px。280×320 的长导航收缩至 128px，内容宽 201px，点击末级导航后横向滚动 72px；缩放条仍保留完整 128px 宽度。
- 浏览器 warning/error 日志为空，已恢复默认视口并保存布局截图。真实 Extension Host 本轮未重复交互验收。
