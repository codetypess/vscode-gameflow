# Color Picker History

Status: Verifying
Date: 2026-11-16
Scope: 原型属性面板的原生取色器与单次撤销/重做边界。

## 1. Context and Root Cause

用户要求在同一次取色器操作中连续改变颜色算一次动作。当前 ColorField 的 React onChange 对每个 input 事件调用 onCommit，经 Inspector、App.edit、DocumentSession.send 发送 replaceDocument；浏览器预览每次推入 past，扩展宿主每次执行 WorkspaceEdit。因此颜色中间值成为独立历史，发送队列仅处理并发确认，不表示用户动作边界。

## 2. Goals

- 取色过程中字段和画布实时显示草稿，结束时只提交一次最终值；一次 undo 恢复开始前的颜色，一次 redo 恢复最终色。
- 填充、描边、文字颜色、页面背景共用规则；原值为 transparent 时也准确恢复。
- 不变化或调回原色不产生历史；结束后再次调色是独立动作。

## 3. Non-Goals

不改变数字/文本字段、不透明度滑块或其他拖动的动作边界，不增加协议、文档字段或宿主历史合并逻辑。

## 4. Behavior and Design

ColorField 持有一次取色的起始值与草稿。原生 input 只更新草稿及 App 的颜色预览覆盖层；原生 change 表示本次取色确认，blur/卸载作为结束兜底，重复结束不得重复提交。使用原生 change 监听器，避免 React 值追踪过滤最终 change。关闭/切换节点时结算已修改草稿；外部颜色变化或锁定时取消过时草稿。保留浏览器对取消取色的原生行为，以最终返回值为准。

覆盖层绑定 pageId、节点 ID 及单个颜色属性，渲染时从最新文档派生，既不进入 DocumentSession，也不写入保存数据；页内与总览都预览。最终色沿用现有编辑接口提交一次，继续接受版本校验、保存与撤销。布局/节点数据仍由原文档负责。

## 5. Implementation Plan

1. 添加纯取色动作与页面颜色预览辅助函数和回归测试。
2. 将字段草稿、原生事件、Inspector 和画布覆盖层连接。
3. 验收真实取色连续变化、undo/redo、透明原值和重新打开；同步基线。

## 6. Testing and Acceptance

- [x] 动作边界测试确认多次预览在结束前无 replaceDocument，结束仅一次提交；字段与画布已连接临时预览。
- [x] 一次 undo/redo 完整恢复起始/最终色；重复结束不重复提交，浏览器颜色输入后的单次撤销/重做通过。
- [x] 无变化/恢复原值不新增历史，连续两次操作互相独立。
- [x] transparent、节点颜色和页面背景预览准确，外部修改/锁定不会被旧草稿覆盖。
- [x] 173 项回归测试、类型检查、生产构建与差异空白检查通过。
- [ ] 原生弹窗内连续拖动的端到端人工验收；当前工具无法可靠操作该弹窗，未声称通过。

纯函数测试覆盖动作边界及无修改、重复结束、过时取消；与 DocumentSession 固定宿主联测断言消息数量及历史恢复。浏览器真实原生取色验证持续 input、关闭后最终 change、预览与撤销，不通过脚本注入事件或内部状态。

验证记录：新增 6 项回归，累计 173 项通过；隔离示例页通过真实颜色输入验证页面背景 #f5f7fb → #336699、一次撤销/重做，以及第二次独立取色后逐次撤销。控件填充 transparent → #a46c92 的单次撤销/重做也通过，验收变更均已撤销。内置浏览器原生弹窗子控件未暴露可操作 DOM，系统 Chrome 处于最小化且当前工具无法恢复，连续弹窗拖动未完成端到端验收；其 input/change 动作边界由纯函数/会话测试覆盖。截图 color-picker-history.jpg 保存本次颜色输入与重做后的显示结果。

## 7. Risks and Rollback

原生取色器事件时序因浏览器而异，必须真实验收 change/blur 及重复关闭；临时覆盖层须在结束/取消时清理。回退字段草稿与渲染覆盖层即可，不影响数据格式。
