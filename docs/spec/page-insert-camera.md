# Preserve View When Adding Pages

Status: Done
Date: 2026-11-16
Scope: 新增页面根时的画布视角。

## 1. Context and Root Cause

用户要求新增界面时当前画布不动。App.addPage 每次新增后调用 fit(全部页面)，将文档内容编辑与相机重算绑定；浏览器复现新增 UIStack 后 transform 从 translate(80.6061px, 56px) scale(0.787879) 变为 translate(57.7725px, 56px) scale(0.616114)。从页内新增还调用 back 恢复旧总览相机，直接移除 fit 仍会跳到另一视角。

## 2. Behavior and Design

- 总览新增 UIStack、UITop、UIScene、UIBox 后保持当前相机平移及缩放，原有页面位置不变。
- 页内新增沿用返回总览并选中新页面的行为，保留当前缩放与原页面屏幕位置。退出页内局部坐标时，将相机平移减去当前页面 frame.x/y 乘缩放，补偿总览坐标原点；不恢复进入页面之前的旧视角。
- 三种界面 UIStack/UITop/UIScene 默认新建尺寸为 750×1334；组件画板 UIBox 为 320×240。右侧顺序摆放、选中/属性面板及内容 Undo/Redo 沿用现有规则。新增页面允许出现在当前视野外，用户可手动平移或使用“适应画布”。
- 提取退出页内的状态清理以接收目标相机；普通“总览”返回继续恢复原总览视角。
- 初始打开、主动进入页面、手动“适应画布”和复制页面的现有导航保持原行为，不增加保存字段或历史事务。

## 3. Implementation and Verification

1. 移除新增后 fit 调用，页内新增显式换算相机，保留普通返回语义。
2. 生产构建/类型检查和共享回归；本问题位于 React 交互层，仓库尚无组件测试环境，不新增镜像源码的测试。使用真实浏览器回归记录 DOM 世界变换及页面屏幕矩形。
3. 总览在非默认平移/缩放下分别新增四种页面根；每次 Undo/Redo 后相机仍不变。
4. 在带非零总览坐标的页面内部新增，核对原页面屏幕位置和缩放；普通进入/返回及手动适应仍有效。验收后撤销新增数据。

## 4. Acceptance

- [x] 总览四种根类型新增前后 transform 一致，原页面屏幕矩形一致。
- [x] 页内新增保持当前缩放与原页面屏幕位置，返回总览并选中新页面。
- [x] 创建内容可一次撤销/重做，相机不参与历史；普通导航及手动适应仍有效。
- [x] 类型检查、生产构建、共享测试、差异空白检查通过。

验收记录：175 项共享测试、生产构建和差异空白检查通过。隔离示例页先平移并缩放至约 74%，分别新增四种根类型，transform 始终保持 translate(1.32701px,39.2px) scale(0.739336)，两个原页面的屏幕矩形逐项完全相同；每次 Undo/Redo 同样保持视角。进入总览 X=1000 的第二页，调整至约 66% 后新增 UITop，原页面矩形新增前后均为 (502.1212,143.3333,275.7576,433.3333)，正确返回总览并选中“顶层界面 3”。页内新增的 Undo/Redo、再次进入/普通返回的视角恢复、手动适应均通过。新增数据全部撤销，恢复两个示例页面，控制台无 error/warn；截图 page-insert-camera.jpg 记录新增后原页面仍保持原位。

## 5. Risks and Rollback

新页面可能在视野外，这是保持当前视角的预期结果；不通过自动滚动、缩放或自动进入新页面补偿。回退新增入口的相机处理即可，不影响文档数据。
