# 原型与 Laya 预制体同步

Status: Draft

日期　2026-11-20

## 场景与入口

策划和开发从一次页面导出开始协作。策划给登录页加「帮助」按钮，开发在 Laya 里加「公告」按钮、给登录按钮挂防连点脚本，还把登录文案改了。同步后应能在两边看到两个新按钮，游戏仍能运行原有脚本。双方改过的同一处文案由人选定。

当前右上角「导出 Prefab」按当前页面生成整份 `.lh`，同时处理图片、导入元数据及来源清单。节点和页面 ID 已写入 `_$id`。底部「预制体」资源模式使用原型节点树和磁盘图片。同步审阅需直接读取实际目标 `.lh`。[导出实现](../../shared/prefab-export.ts) · [现有资源模式](11-prototype-ui-layout.md)

建议复用右上角的入口。首次生成时沿用现有导出并记录共同版本；目标已存在时，进入「同步预制体」。初次遇到无同步记录的同名文件时先审阅关联。页名、导出名或目录变化时同时显示已关联路径和拟用路径，由用户确认继续关联、重新定位或生成独立文件。明确选择当前页后方能操作。

## 页面与操作

沿用正在实施的 PSD 同步窗。页面名与目标相对路径位于标题栏，左侧为完整节点树，右侧为原型与目标的两幅画面，底部为「待决定 / 已选」和「预演应用」。窗口可从右下角调整宽高，重开记住尺寸。切换节点、打开明细时外框稳定，内部滚动，底部操作始终可见。窄屏时树移到画面上方。[PSD 同步方案](page-psd-sync.md) · [当前同步窗](../../webview/editor/page-sync-dialog.tsx)

1. **定位节点。** 用上次同步、当前原型和目标文件的节点并集形成完整树。树中显示名称与变量名，变更分支默认展开，未改节点可选中。新增绿「+」、删除红「−」、修改黄「~」。树和双画板使用相同标记，缺失的已删除节点在原位置显示虚线框。只更新了脚本时，仍能展开整棵树，待同步为零。
2. **切换「当前 / 同步后」。** 当前画面分别取原型工作副本与磁盘 `.lh`。原型用内置资源，预制体预览按目标自己的层级、布局和资源引用绘制可识别的静态 UI。脚本显示在所属节点下，选中时定位预制体的挂载对象并显示参数。动画和未知组件列出类型、挂载点及引用。资源缺失显示占位和路径。
3. **逐项采纳。** 画板下方显示上次值与双方当前值。单边新增给出目标建议，双方改同一字段时可选择来源或「本轮跳过」。选择后自动进入「同步后」，两幅画面按本轮所有决定一起更新，随时可切回「当前」。整棵新增子树计为一项，展开或点选其文案均指向同一决定。
4. **预演与提交。** 待决定项全部处理或明确跳过后，可打开「本轮应用明细」。分别列出原型编辑、实际目标 `.lh` 和随附资源的写入、受影响的引擎组件及跳过项。可返回调整，确认时才提交。跳过项在下次比较继续出现。[登录页交互稿](../design/page-prefab-sync.html)

实现时从现有同步窗提取窗体尺寸、树、选中框、预览切换、逐项决定与明细展示。保留 PSD 与预制体各自的读取器、可同步字段、预览生成及提交流程。预制体由实际 `.lh` 生成静态预览，按路径修改同一关联文件并保留引擎字段。页面与预制体有独立同步记录，同一页面的 PSD 同步进度单独保存。

## 合并规则

| 相对于上次同步发生的变化 | 默认建议及实际写入 |
| --- | --- |
| 原型新增「帮助」，预制体新增可识别的「公告」 | 两项分别建议写入对方。父级已配对、身份唯一且顺序相容时可以一起应用。每个带文案的新增按钮按一棵子树计一次。 |
| 同一节点的不同字段分别被修改 | 独立合并。例如原型改宽度、预制体改文案，两项可同时采纳。双方把同一字段改成同一个值时直接记为一致。 |
| 双方将同一字段改成不同值 | 并列展示三个值。例如「登录」分别变成「进入游戏」和「开始冒险」。选一个值写入另一侧，或跳过该字段。 |
| 预制体添加脚本、动画、材质、特效、未知组件或属性 | 原样保留在现有预制体对象和子树中，显示「仅预制体」，不计入待处理。原型独有的交互、备注和编辑状态同理保留在原型。 |
| 删除、移动及重排 | 单边删除列为待确认，列明所有受影响子孙、组件和已知引用。删除遇到另一侧修改或独有后代时默认保留并待决定，可跳过或先迁移子项与引用。同一节点被移动到不同父级、位置约束互斥时显示冲突。 |
| 独立新增同名、重号或身份不明 | 稳定 ID 与映射确定对象；名称和路径用于定位。两个不同 ID 的同名控件可并存，若变量名等约束冲突则先改名或跳过。重复 ID 提示具体位置并暂停相关子树。 |

首版共享字段建议采用白名单：能无损表达的 UIButton、UILabel、UIBox 等控件结构、父子顺序、文案和经过往返验证的基础几何。控件改型、带约束布局的歧义及变量导出名变化单列为人工处理或跳过。`.lh.name` 可能是变量名，不能直接覆写原型显示名。预制体新控件使用原型默认内置外观。皮肤 UUID、图片内容、动画、业务脚本与其他引擎字段继续由目标工程管理。原型首次推入的新控件按现有导出策略提供初始资源，需要新文件时一并列入审阅。同步已有字段的操作只触及已选内容。

## 同步记录与写入

- 建议在原型同目录保存可随项目提交的 `<文档名>.prefab-sync.json`，以文档 ID、页面 ID 和目标相对路径区分关联。记录版本、节点 ID 对应关系、上次双方同意的共享字段值、父级和相对顺序。首次生成成功才记录起点；旧项目首次接入按 ID 提议配对，同值建立基线，不同值或单侧存在的对象由用户决定，单凭缺失无法推断历史删除。
- 新增控件跨侧导入时尽量保留目标合法且未占用的身份，否则分配目标 ID 并记录映射。同批父子和控件引用一起重映射，目标模型验证后才可提交。以稳定同级节点为位置锚点保留原有的引擎子节点顺序；同一空隙的独立新增须使用双方一致、可预览的顺序。
- 预制体从磁盘读入完整对象树，针对已选路径编辑。脚本属性、未知组件及专属子树直接沿用原对象，保留既有 `_$id`、`_$ref` 及资源 UUID。删除会损坏已知引用时要求先解决依赖。引擎专用内容只作为上下文浏览，不反复提示。
- 原型编辑走现有宿主文档与历史机制。比较使用当前工作副本和磁盘目标。提交前复核工作副本版本、目标及同步记录的摘要，检测未保存的目标文件。外部变化后刷新比较，按身份及三个值重新验证先前选择。
- 提交把所选原型事务、目标文件、所需新增资源和同步记录作为一组处理。若需保存原型工作副本，预览明示将随当前未保存编辑一起保存。先备份将变动的内容，成功才推进已处理字段的共同版本；跳过项保留旧共同值。失败恢复并允许重试，中断恢复和条件写入需避免回滚覆盖别人随后写入的版本。撤销原型编辑后按新差异再次审阅。

## 实施与验收

| 阶段 | 验收场景 |
| --- | --- |
| 只读比较与首次关联 | 用首次生成、已有同名文件、目标改路径、复制页面四种情况验证身份；审阅及取消后所有文件摘要相同。 |
| 与 PSD 预览一致 | 两种窗口用相同操作定位未改节点、新增文案子节点及已删节点。采纳、跳过后逐侧核对「当前 / 同步后」、颜色符号、计数与应用明细。拖动调整后重开保留尺寸，展开树和打开明细时外框稳定。只有脚本变化时，仍可查看挂载点和参数，待同步为零。 |
| 双向合并与引擎保留 | 同步「帮助」与「公告」后，两侧各有这两个按钮且每个只有一份。原有防连点脚本、参数、未知字段、子树顺序及资源引用在 Laya 中可用。 |
| 冲突与重复同步 | 逐字段覆盖同值、不同字段、不同值、删除与修改、重排和重号。应用后重开，仅跳过项仍待处理；处理完再次同步为零项。 |
| 提交与恢复 | 覆盖预览后外部改写、原型未保存、第二个文件写入失败、中断恢复和重试。用真实 Laya 工程保存、重开并运行登录页验证引擎对象保真。 |

本次交付为方案和可操作的页面设计稿。实现之前优先用一个真实 Laya 往返样本验证节点身份、控件识别及可逆字段；遇到不可可靠重建的内容时收窄该字段的回写范围，并在详情里标明原因。
