# Inspector Overlay Scrollbar

Status: Done
Date: 2026-11-16
Scope: 原型属性面板滚动条不占用内容布局宽度。

## 1. Context and Root Cause

用户切换不同控件/属性折叠状态时，属性面板在有无纵向溢出之间变化，字段跟随收缩和重新排版。修复前 `.inspector-content` 使用 `overflow-y: auto; scrollbar-width: thin`；Windows 浏览器实测外宽 278px、内容区宽 268px，原生滚动条占用 10px。宽度变化发生在滚动视口，不在面板定位或字段宽度计算。

## 2. Goals and Non-Goals

有滚动与无滚动时字段可用宽度保持一致，滚动条浮于右侧既有内边距内；保留滚轮、拖拽、轨道点击、键盘与焦点自动滚入。属性面板的定位、最大高度、折叠和节点切换规则保持现状。本次只修改原型属性面板，不扩展到层级树或 PSD 工作区。

## 3. Design

沿用当前 Radix UI 体系增加 ScrollArea 封装：原生视口继续负责内容滚动并隐藏原生滚动条；独立竖向轨道绝对定位，不参与布局。轨道宽 10px，拇指放在原有 12px 右内边距内，不遮挡输入框。按用户追加要求采用接近 macOS 的显隐：空闲时隐藏，滚动时显示，停止约 800ms 后淡出，悬停/拖动滑块期间保持显示；无溢出时不显示。视口使用 `min-height: 0` 在原有 flex/最大高度约束内收缩，短内容自然收拢，不强制填满面板。单选属性和多选摘要共用滚动区，切换节点按现有 key 重置视口。

## 4. Implementation and Validation

1. 添加 Radix ScrollArea 依赖和薄封装，替换属性内容区的原生滚动容器。
2. 用实际页面的短/长属性内容及折叠状态验证内容宽度相等，原生滚动条占用为 0；核对窄窗口和面板折叠。
3. 验证滚轮、拖拽拇指、轨道点击、键盘/Tab 焦点滚动可到达底部；操作不平移画布、不更改文档。
4. 类型检查/生产构建、现有测试和差异检查。现有测试为 Node 共享逻辑套件，无 DOM/CSS 布局运行器，无法复现操作系统滚动条占宽；本项布局回归以实际浏览器尺寸断言和操作验收记录，不添加 CSS 文本断言。

## 5. Acceptance

- [x] 有无溢出时，视口宽度与字段可用宽度一致，滚动条不占位。
- [x] 空闲隐藏、滚动显示、停止淡出，操作滑块期间保持显示。
- [x] 滚轮、拖动、轨道点击与键盘/焦点滚动通过，底部属性可访问。
- [x] 单/多选、折叠展开及短内容高度正常；画布视角不受滚动影响。
- [x] 窄窗口无横向溢出，现有测试、构建与差异检查通过。

实测记录：750×1334 样例中选择按钮文案，展开属性时视口高 1033px、内容高 1215px；折叠尺寸与约束后视口/内容均高 926px。两种状态内容宽均为 278px、名称输入框宽均为 187px，滚动条占宽为 0。End 键滚至底部 182px，Tab 焦点可到达描边宽度；滑块拖拽使 scrollTop 从 58px 变为 152px，轨道点击从 0 到 182px，滚轮正常。各过程画布变换保持一致。多选摘要自然收拢至 222px，面板收起高 36px；720×800 窗口的视口 clientWidth/offsetWidth/scrollWidth 均为 278px，无新增横向溢出，临时视口已恢复。

空闲时轨道卸载，滚动时为 visible，拖拽期间保持 visible；两张同一滚动位置的最终截图只有右侧轨道区域发生像素变化，字段位置一致。截图：`inspector-scrollbar-active.jpg`、`inspector-scrollbar-idle.jpg`，对照图 `inspector-overlay-scrollbar.png` 保存在本次可视化输出目录。177 项共享测试和含类型检查的生产构建通过；保留既有构建包大小提示。安装依赖时 Vite 重新预构建曾产生旧缓存混用的热更新错误，完整刷新后完成上述验收，日志未新增同类错误；`npm ls` 确认 React/React DOM 18.3.1 共用同一安装。

## 6. Risks and Rollback

主要风险是嵌套 flex 使视口不正确收缩，或覆盖轨道挡住右侧控件；通过实测长内容和右侧输入框位置检查。回退 Inspector/CSS/ScrollArea 与新增依赖即可恢复，不涉及文档格式或持久化。
