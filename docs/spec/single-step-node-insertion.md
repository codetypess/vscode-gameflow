# Single-Step Node Insertion

Status: Done
Date: 2026-11-24
Scope: 原型页面底部添加菜单、常用控件快捷入口与字母快捷键

## 1. Context

当前底部添加菜单和常用控件按钮先切换到放置工具，用户还要再点击页面才能创建节点。这个二段流程增加一次无必要操作，也让工具按钮表现得像持续模式而不是添加命令。

## 2. Goals

- 选择添加菜单中的控件后立即在当前编辑层创建并选中新节点。
- 点击底部常用控件图标或按对应字母快捷键时执行相同的一段式添加。
- 保持当前层、组件根、锁定保护、撤销和节点默认尺寸等既有语义。

## 3. Non-Goals

- 不改变画板创建、引用画布组件、图层树右键新增或画布右键指定坐标新增。
- 不增加拖拽创建、连续绘制模式或新的文档字段。

## 4. Current Behavior

控件入口调用 `chooseInsertTool` 保存待放置类型。下一次点击画布时才通过 `placeCanvasComponent` 创建节点，随后选择节点并回到选择工具。

## 5. Proposed Behavior

控件入口直接向当前编辑层插入节点。节点使用该层可用区域的中心作为默认位置；连续添加沿用现有按同级数量计算的 12px 错位。成功后选中新节点，菜单关闭，画布保持选择工具。总览中控件入口继续禁用。

字母快捷键与对应快捷图标一致，按一次添加一个节点。`V` 与 `H` 仍分别切换选择和抓手。画布右键新增继续使用右键坐标，不受默认中心位置影响。

## 6. Design

- 将已有 `addLayer` 的中心插入算法提取到 `canvas-scope` 纯操作，供图层入口和底部入口共用。
- 工具状态只保留选择和抓手，不再保存控件类型；画布点击因此不会延迟创建节点。
- 锁定、非法父级和组件根解析继续通过 `insertNode` 与既有编辑边界拒绝提交。

## 7. Implementation Plan

1. 增加可测试的一段式中心插入操作并让现有图层新增复用。
2. 将菜单、快捷图标和字母快捷键改为直接调用新增命令，移除待放置工具分支和过时提示。
3. 同步产品基线并运行共享测试、类型检查和生产构建。

## 8. Testing Plan

- 纯测试覆盖页根/当前容器中心插入、连续错位、组件根归属和锁定拒绝。
- 运行 `npm test`、`npm run build` 和 `git diff --check`。
- 浏览器检查菜单项、快捷图标和字母快捷键均单次创建，节点被选中且下一次画布点击只执行选择。

## 9. Acceptance Criteria

- 菜单、快捷图标和字母快捷键不再进入待放置状态，单次操作创建一个节点。
- 新节点属于当前编辑层，位于默认中心并被选中；一次撤销移除本次创建。
- 总览禁用、锁定保护、画布右键坐标新增和页面新增行为保持不变。
- 自动检查与生产构建通过，规格和基线与实现一致。

## 10. Risks and Rollback

主要风险是默认位置不在当前可见层或快捷键误触。复用现有中心插入、字段焦点过滤和文档事务降低风险。回退入口调用与工具状态即可恢复二段放置，不涉及数据迁移。

## 11. Verification

- `npm test`：385 项共享测试通过；新增覆盖当前层中心、连续 12px 错位、组件根归属及锁定/非法父级拒绝。
- `npm run build`：扩展与 Webview 类型检查、扩展打包和 Vite 生产构建通过；保留既有大包体提示。
- `git diff --check`：通过，仅报告工作区已有 CRLF 转换提示。
- 浏览器预览：常用“文字”图标单击后立即新增并选中，随后单击画布未再次新增；添加菜单中的“输入框”使图层数 `4→5`；字母 `T` 使图层数 `5→6`。菜单标题显示“添加到当前层”，没有待放置高亮状态。
