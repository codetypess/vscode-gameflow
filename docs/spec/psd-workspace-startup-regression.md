# PSD 工作区启动与页面绑定隔离

状态：Done（2026-11-19）

## 1. 背景与根因

打开 GameFlow 初始 mode 已为 prototype，但宿主恢复上次 currentPsd 后发送 psdEditorInit，usePsdEditor 在异步解码成功后无条件调用切图导航回调。因此数据初始化被误当作显式导航，且延迟完成会覆盖用户随后选择的工作区。页面后台 PSD 加载使用独立 pagePsdResult，并非触发跳转的来源。

截图中星海示例新增 artPsd 来自上一轮直接编辑示例和生成脚本，打开切图的代码没有写入页面绑定。示例不应预先把打开过的 PSD 当作页面来源；应保留未绑定入口供用户明确选择。

## 2. 目标

- GameFlow 打开、重新打开以及恢复上次切图会话均先显示原型画布。
- 明确执行打开切图仍进入切图工作区；同一 PSD 再次打开可聚焦而不丢失未同步编辑。
- 初始化、重载、撤销与解码完成均不得触发导航。
- 打开、恢复和查看切图不新增或修改 artPsd，不改 GameFlow 内容或保存其文件。
- 仅页面的绑定/生成动作建立绑定，进入既有可撤销编辑与正常保存流程。
- 撤掉星海示例和生成脚本中擅自预设的 artPsd，保留已有显式图片槽位。

## 3. 非目标

不取消切图草稿与 sidecar 保存，不拆分工作台统一保存，不关闭编辑器全局自动保存设置，不迁移已有用户绑定或清除其他文件中的绑定。

## 4. 设计

增加独立 Host→Webview psdEditorReveal 消息，由 GameFlowEditorProvider 仅在明确打开切图命令成功时发送。psdEditorInit 只初始化会话和像素。usePsdEditor 在收到 reveal 时立即执行导航，解码完成只设置资源；同文件打开只发送 reveal，不重新初始化模型。恢复/ready/revert 不发送 reveal。

页面绑定继续由 pagePsd choose/generate 的显式动作和单次页面事务负责。示例生成脚本不自动设置 artPsd。

## 5. 实施

1. 添加浏览器回归重现恢复 PSD 抢占原型画布的问题。
2. 拆开初始化和导航消息，删除示例预设绑定并同步说明与基线。
3. 原生宿主覆盖打开/恢复/同文件聚焦不绑定、不改 GameFlow 磁盘；浏览器覆盖实际 hook、解码竞争与未绑定入口。

## 6. 验证与验收

- 恢复初始化解码成功后仍显示原型。
- 显式 reveal 即时显示切图；解码尚未完成时用户切回原型，完成后仍保留原型。
- 重载初始化不改变当前工作区；已有 PSD 仍可手动查看。
- 未绑定页面打开 PSD 后切到美术仍显示生成 PSD / 绑定 PSD，且不产生 GameFlow 编辑或保存请求。
- 原生打开/恢复/再次打开同文件后页面模型与磁盘文本完全不变，原有绑定保持不变。
- 共享测试、PSD 宿主、相关浏览器回归、生产构建和 diff 检查通过。

## 7. 风险与回退

显式打开仍需单独发送 reveal；回归同时验证该通路以防修复后打不开切图。旧初始化消息无 reveal 意图，默认保持工作区。回退可恢复协议与回调，但会重新引入抢占导航。

## 8. 验证结果

- 新增 test/psd-workspace-startup-browser.cjs 在修复前稳定失败于“恢复解码后仍应在原型”；修复后通过。使用真实 PSD Worker，覆盖恢复、明确打开、同文件聚焦、延迟解码后用户选择保持、重载不导航，以及未绑定页面的双入口。检查实际 replaceDocument/save/pagePsd/psdEditorEdit 等消息均未发出。
- test/workbench-psd-smoke.ts 原生检查明确打开发送 reveal、同文件聚焦不初始化、恢复初始化不 reveal；打开及重开后页面与磁盘文本无绑定变化。页面已有明确绑定的纯加载也保持原文本及磁盘。
- npm test：358 项通过；npm run test:psd-host：48 项真实 VS Code 检查通过。
- test/page-psd-browser.cjs：明确绑定、生成即绑定、取消、撤销重做、多页资源隔离、保存及重开等既有回归通过。
- npm run build（含双端类型检查）与 git diff --check 通过。
- 星海示例文件恢复未绑定，生成脚本不再写入 artPsd；没有删除其他用户文件中的既有绑定。
