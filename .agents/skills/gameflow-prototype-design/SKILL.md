# 原型设计

在策划的工作目录交付可编辑的 `*.gameflow.json`。输入可以是策划文档、对话中的需求、附图及现有原型。先读用户指定的材料和已有约定。用户只要求分析时，交付页面清单和设计判断即可。

## 从材料还原玩家流程

1. **沿玩家动作找页面。** 对每个玩法追问“从哪里进入、看到什么、可以做什么、操作后在哪里、如何返回”。查看正文、规则表、流程图、异常分支和图注。为每个有依据的入口、详情、确认、结果、失败或空态找到归属。已有系统的入口可以是外部上下文，只为本次范围内的界面建画板。
2. **对读手绘草图。** 实际查看每张图；文档中的内嵌图、扫描页也按图阅读。按“图号／方位 → 标注或形状 → 文档段落 → 页面与控件”对照。先辨认画框、标题、分区、遮罩、重复单元和箭头，再结合文字判断箭头表示跳转、操作反馈还是尺寸标注。保留有意的先后、分组、主次和相对位置，按设计尺寸整理草图的间距。看不清的字、孤立的框、没有明确落点的箭头，记下具体位置与疑问。无法访问某图时，交代缺失材料，先覆盖可读内容。
3. **把证据和决策对应起来。** 明示要求记为 `confirmed`，为补全流程所做的可逆判断记为 `inferred`，冲突和未决业务规则记为 `question`。来源写到 `requirements[].source`，如“征集案 §2.3；草图 B 右下角”。遵从用户指定的版本或优先级。没有指定时，文字提供明确的业务规则，图提供明确的空间与操作线索。两者对同一规则说法不同时，列出两处出处、采用的暂定处理及其影响。不要用笔迹猜价格、数值、权限或按钮效果。
4. **决定画板粒度。** 独立任务或导航目的地用 `screen`。需要在当前上下文做出决定、查看详情并返回的覆盖层用 `modal`。筛选、选中、展开、禁用、空列表等通常归入原页面，写明“触发条件 → 可见变化／可执行操作”；若需求要求并排审阅明显不同的状态，可增加命名清楚的状态画板。组件模板另建 `UIBox` 画板。沿主线和各个分支复走一遍，把遗漏的界面补齐。
5. **建立覆盖关系。** 生成时维护一份简短的“需求与来源 | 页面／页内状态／模板 | 操作与去向”对照。同一页面可以承接多条规则。未决定的分支保留为问题；已确认、能够独立完成的部分继续生成。

例如，文档写“点奖励查看详情，未解锁时显示条件”，草图只画了三行奖励和指向浮层的箭头。应建奖励页、详情弹窗和一张奖励项模板。列表引用该模板，锁定条件放到条目或详情的对应状态。若关闭弹窗的手势没有约定，就把返回方式标作推断。

## 生成可编辑画板

- 写文件前读[画板与引用](references/boards.md)。主窗口统一使用 **750 × 1334** 竖屏设计尺寸，按该画幅整理草图分区。弹窗根据文案、控件、按钮及留白确定实际宽高，列表项模板使用单项的自然尺寸。在改已有原型时先重读当前文件，保留原有 ID、人工摆放、资源绑定和作用域内的实例编辑，只修改这次需求涉及的内容。
- 按“页面 → 有共同职责的区域 → 控件 → 可编辑部件”组织层级。能独立移动、裁剪、复用或管理一组子项的区域才需要容器。让节点名说明业务用途，玩家文案写到可见文字上。使用足以评审的示例数据，数值彼此一致。
- 固定设计稿优先给出父局部坐标与明确宽高。等距排列用横排、竖排、网格。只有父尺寸变化后确实要贴边、居中或拉伸的节点才添加相应轴的约束。草图中画在中间、靠近边缘，本身不足以决定自适应行为。
- 数据列表用 `list.cellPrefab` 引入独立条目画板。通用整块内容可用 `container.prefab` 引入源画板。主页面只保存实例或列表，模板内部保留真实控件层级。
- 新建或替换占位图时，只使用 GameFlow 内置资源。在图片或按钮皮肤的资源槽中填写 `builtin` ID。立绘、插画用 `image/default`，头像用 `icon/user`，底板和控件状态选用内置色块或皮肤。
- 根据[组件与组合部件](references/components.md)选型。尤其核对滑块、进度、复选、单选、单选组和下拉框的子节点与字段绑定。可直接打开[公会征集示例](references/guild-supplies.gameflow.json)查看主页面、条目模板和弹窗如何组合。

## 验收与交付

- 重新读取最终磁盘文件；用随技能提供的 [GameFlow v5 Schema](references/gameflow.schema.json) 检查字段，用[画板与引用中的复核步骤](references/boards.md#复核生成结果)检查跨对象关系。能使用 GameFlow 时再在画布核对遮挡、裁剪、长文案、铺排、部件状态和选择层级。
- 按玩家操作逐步走查，检查主操作可见、触发方和返回路径能对上，模板里也有足够信息辨认每个条目。将已确认需求逐条对照实际落点；任何暂缺内容说明原因。
- 交付文件链接，简列业务页、弹窗和复用模板，以及影响判断的假设、草图冲突和待确认项。写明实际做过的验证。除非用户另有要求，覆盖说明直接放在回复中。
